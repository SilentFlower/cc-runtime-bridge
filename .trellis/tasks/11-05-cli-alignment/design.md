# 固定 293 终端 CLI 对齐设计

## 目标与边界

以未修改的固定官方 2.1.293 交互终端主请求为参考，让结构化单轮桥接经过 CLI 的提示词、工具和上下文装配，再沿用已有的原生单次发送。终端 UI、自主工具执行、标题或建议推理不进入桥接流程。

本轮继续使用外部请求/事件 schema 1 和常驻私有管道 schema 2；不增加 SDK/CLI 模式选择器。普通主会话的默认行为改为 CLI。六种已有 requestClass 继续保留其真实类别与代理关系，不把辅助、压缩或子代理一律变成主会话。

## 输入合同

| 输入 | 本轮语义 | 显式值保护 |
| --- | --- | --- |
| 省略 tools | 无工具，与显式 [] 一致 | 不加入内置、延迟、搜索或占位工具，发送前同样检查空列表 |
| tools=[] | 完全禁用本轮工具声明 | 不混入默认、延迟、占位或工具搜索声明 |
| 显式 tools 数组 | 该数组为完整可用列表，不叠加 CLI 内置工具 | 保留名称、描述、schema、顺序和已支持显式字段；无法无损表达时在发送前返回 422 |
| 省略 system | 原生 CLI 默认正文 | 模型、实际工具集和环境参与原生生成 |
| 显式 system | 对应 CLI --system-prompt，替换默认正文；空文本/空数组同样按显式值处理 | 保留原生身份及归因；继续拒绝已封口 billing 前缀及不能保留的缓存块 |
| 省略模型可选参数 | 采用原生 CLI 对当前模型及配置计算的默认值 | 不再人为固定 thinking=disabled |
| 显式模型可选参数 | 保留当前支持的 max_tokens、temperature、thinking、tool_choice、output_config 语义 | 继续执行发送前保留检查，原生规则改写显式值时明确拒绝 |
| user/assistant 历史 | 原生消息工厂建立业务历史，再装配当前类别实际需要的 CLI 提醒 | 不把 tool_result 当作新的人类终端输入，不丢弃 thinking 签名或工具关系 |

自定义 schema 是桥接已有的结构化能力，不等于终端 --tools 接受任意 schema。对这类输入的验收应验证已确认的完整列表规则及相应 CLI 上下文，不声称存在 CLI 不支持的原生命令参数。

## 原生装配机制

### 已核对的入口

- 核心模块 /$bunfs/root/chunk-g263vvvn.js 已导出 VA、Kz、LT、Uz：VA 根据工具、模型和选项产生默认 system；Kz 处理显式 system 与原生追加段；LT/Uz 按当前原生根构造用户/系统上下文。
- /$bunfs/root/chunk-h8et53c1.js 已导出工具目录 Bq 及池构造 k0t；Bq.getAllBaseTools、getTools、assembleToolPool 分别关联原生工具集合、筛选和装配。终端还经 /$bunfs/root/chunk-vjrdrpdq.js 的 $0t、F0t 处理最终工具池。
- /$bunfs/root/chunk-57d0836j.js 的 u1e() 生成主线程 querySource，默认是 repl_main_thread，输出风格可能增加后缀。
- 交互主入口 /$bunfs/root/chunk-848z1p5h.js 已确认以 isNonInteractiveSession=false 建立工具上下文，调用 VA/Kz/LT/Uz，再进入原生查询流程；核心 K_t 是更下层构造器，不会替调用方完成全部终端提醒装配。
- API 模块的身份选择器 Nrr 依据真实非交互/追加选项选择前缀；本轮不复制该文本或覆盖 recordedCliPrefix 伪造身份。

隔离探针已验证原生 pie 生成初始附件、OM 查询引擎生成日期和归因等后续提醒，再经 OM 的 deps.callModel 边界进入 K_t。工具、权限、状态存储及访问器均采用实际导出的官方工厂；默认工具 schema、消息块、静态 system 和模型默认参数与同配置交互参考逐项相同。正式适配沿用这一边界，不手写提醒文本，也不接收模型输出继续执行查询循环。

交互参考和桥接均采用专用配置中已确认的合成 API key；首次在终端确认密钥的参考另行保留，它会选择不同的权限初始状态，不能混作同一配置。控制层明确配置的 API key 在专用 CLI 配置里使用原生 Ae/VH/Lle/Iyr 记录本地使用确认，仅写入 CLI 自身的标识；已拒绝的密钥明确失败，不修改其决定。该步骤不登录、不刷新、不保存完整密钥。绑定 Hoe 与 $8e 注册实际 CLI 内置技能，并采用原生交互标志和 markdown 问题预览格式。

### 数据流

1. parseInput/prepareInput 验证结构化输入与六类上下文，主线程来源采用 CLI 合同；头部仍按既有保留/删除规则处理。
2. worker 在每轮新建的原生根内，按禁用内置工具的原生路径取得默认参数、业务历史和 CLI 上下文；工具仅来自调用方显式列表。静态原生绑定及下述已验证的静态正文可跨轮复用，环境提醒、权限及取消状态的可变结果不得跨作业缓存。
3. 使用原生 pie 与 OM 装配 system 和提醒，生成与实际工具集及请求类别一致的输入。默认主请求使用交互 CLI 选项和 human 消息来源；工具结果、子代理、压缩及辅助消息采用各自真实来源。每轮独立建立权限、工具、状态存储、任务视图及文件读取状态。
4. OM 的 deps.callModel 只允许进入一次 K_t；其 fetchOverride 取得正文并完成业务字段保留检查，之后才交给受控发送。worker 预热不传发送回调，取参后立即取消，模型发送数为零。DISABLE_AUTO_COMPACT 禁止自动辅助压缩，runQuery 和 canUseTool 拒绝本地代理和工具执行；显式 compaction 仍保留。
5. 复用 K_t 内部 yN 已创建的官方 SDK 和发送上下文，在同一 fetchOverride 中合并合法扩展头并映射 stream，再由 Ree 唯一实际发送。stream 已相同时保留 SDK 原文，避免重复序列化。桥接独占原始 Response，直到读取收口前都不交给 SDK；回调成功或失败后立即取消原生调用，并用次数守卫禁止重试。无需第二个 SDK 客户端重新构造请求，attempt 仍为 1。
6. 独立本机 TLS 接收器保存最终正文和原始接收头，核验 CCH，再生成日志样本；cc_prepared 继续标为 JS 传输前观察值。

### 有界的发送性能优化

- 保留私有 schema 2 的现有 JSONL 格式；解码已解析的载荷时直接复用同一校验器，不再 JSON 序列化后重新解析。性能驱动同样只解码一次，仍完整消费诊断、响应和 idle，不能省略事件降低计时。
- cc_prepared 的正文、原始字节数及 SHA 在 Ree 前固定。原始正文和头仅通过私有管道传给控制层，RequestTrace 先注册输入、控制配置及原生头秘密，再统一脱敏持久化，避免运行时与控制层重复扫描完整 CLI 正文。运行时错误仍由本轮 Redactor 处理。
- 在参数全部校验、cc_prepared 快照固定后，并行等待其有背压的输出与唯一 Ree 发送；只有两者均成功，才交付 response_headers 和正文。任一失败立即取消原生调用，等待两方收口，并释放已经取得但未交付的响应，不增加发送或重试。
- URL 凭据脱敏直接查找 :// 后的凭据部分，保留协议及地址；避免为每个普通字母重复尝试匹配任意长度的协议名。持久结果仍覆盖原有 URL 凭据及合成秘密用例。
- 默认 prompt 的复用仅限下节明确的静态部分；工具选择、权限或项目读取结果不得跨作业缓存。字节码探针及额外预热仅作研究，不作为达标依据。新的最终嵌入代码仍须重新构建、原生回归及五轮配对。
- 配对报告保留两方每轮实际接收正文、system 的 JSON 字节数及工具声明数量，以及原输入、标杆身份和计时边界，用于解释缺省装配的工作量；历史 1.10 结论不改写，不靠补齐标杆负载或删掉桥接默认工具消除差距。

### 用户已选择的折中优化：静态正文复用

- 继续以固定 293 原生装配为正确性基准；不复制 vm2api 的 303 文案，不增加运行模式菜单，也不将兼容性或 CCH 校验解释为账号免封保证。
- 先读取原生静态/会话段、钩子、默认模型与失效机制的真实定义，再确定可复用单元。仅共享不可变文本及其确定性生成结果，不能仅凭同一模型或连续几次输出相同，就缓存整个 VA、LT、Uz 或最终请求。
- 每轮继续新建根、权限、工具与取消状态；日期、工作目录、memory/项目读取、消息提醒、六类来源、session/prompt/agent、billing、metadata 与最终原生 CCH 均按当前输入处理。提示词钩子及原生失效副作用不能被复用路径跳过。
- 缓存键必须覆盖实际证明的全部依赖；模型、工具集、输出风格、配置或功能条件参与正文时，应重新计算对应值或退回原生路径。未知条件、首次缺失及失败保持原生生成或原有错误语义，失败结果不入缓存；共享容器有界且由同一物理运行时持有。
- 原版预加载和精简静态入口采用相同适配合同，构建来源、所有新增文件及配方同步登记。专有正文仍由固定来源取得，不提交到 Git。
- 定向验证包括：命中时确实减少静态生成；模型/工具变化、显式 system、相同/交替 session 与配置变化不串值；动态日期/提醒和钩子仍生效；原生基准与复用路径的完整最终正文仅允许既有逐项归一化，CCH 独立核验。之后重建候选，执行原生套件、重复构建、独立部署和原五轮配对。
- 复用方案不得删减 CLI 正文、提前 ready 或隐藏初始化成本。保留旧性能失败证据；当前不继续追赶相对速度目标。

首个落点为精简构建中的六个纯正文格式化工厂：KLo、XLo、QLo、nNo、sNo、pNo。固定来源的函数摘要及其实际依赖在构建转换器中登记；变形或缺失直接拒绝构建。相关 RVt、AVt、bR、T、CN、HE、TLo 等读取仍在每次调用时执行，条件结果参与键；kg 和 $Lo 的纯函数定义一并固定。缓存只持有不可变字符串，每个工厂只保留最近一次可缓存的条件及结果，单项键和值不超过 64 KiB；六项合计最多 384 KiB，计算异常及超限结果不入缓存。命中直接比较原始条件，不编码键或创建格式化闭包。原生 VA、段落钩子、prompt ablation 和全部会话生成继续运行；原版入口作为未改写对照，两份入口保持相同请求合同。该实现不缓存 VA 的最终数组、原生 sections Map 或 memory 读取结果。

- CHK-002：修正 OM 的公开接口注释，准确描述首次受控发送和响应读取收口后取消原生解析的边界。

- 体积与启动的下一项有界候选：原生顶层命令对象明确为 local/local-jsx，且具有 name、description 及函数形状的 load/call 时，仅将执行函数替换为明确拒绝。保留完整元数据、可用性及隐藏判断；不改变 prompt 类型的技能及其正文，不触及未知对象或工厂。该边界与既有工具 create 守卫一致，须以最终 CLI 正文及原生套件确认，再作为构建配方的一部分记录。

### 首发装配链试验

用户已选择继续验证缩短原生首发装配链，沿用 CHK-001 的修复授权及原验收标准。先在隔离研究中验证固定查询模块的单轮特化：保留首次 deps.callModel 之前的原生处理及完整参数表达式，只替换随后面向模型事件、工具结果及下一轮的消费逻辑；外围 finally 和取消收口保留。不手写 CLI 提醒、工具声明、归因或请求模板，不改变 K_t/SDK/Ree 的实际首发路径。

原版未改写入口和当前候选作为独立基准。试验须证明首次参数及最终出站等价，再做同窗口暖调用对照；未证明收益或发生任何合同差异时只保留研究证据。若有收益再纳入正式转换器，固定函数摘要、AST 形状和守卫，重做两份入口的原生回归及最终产物准入。静态工具 schema/描述复用作为后续候选，须先查明其实际依赖、原生缓存命中及失效条件。

### 来源与有效上下文

普通主请求使用原生 CLI 主来源；子代理、workflow、compaction、auxiliary、side_reply 保留原有真实类别映射，并核对原生父子语义。session、prompt、agent、parent、metadata 和 billing 必须指向同一上下文。

控制层与原生输出的来源必须一致。输出风格等配置造成来源后缀时，需要同步有效来源或在发送前明确拒绝不能表达的配置，不能只改变出站值而让日志继续写 sdk。删除引擎和性能脚本主动设置的 SDK client-app 标识，User-Agent 交由原生 CLI 构造。

### 显式参数与原生补充段

现有 ensureSubset 对 messages 使用等长数组比较，不能直接用于加入 CLI 提醒后的整段数组。保留检查需分别覆盖原业务消息及原生新增段：业务消息的内容、顺序、thinking/工具字段保持语义一致；新增提醒按明确类型、来源和位置与参考结果比较。不得通过一律忽略所有 system-reminder 或删除全部 messages 差异让验收通过。

显式 tools 继续做完整列表检查。工具声明、system 中的工具说明、延迟工具目录和工具相关提醒必须描述同一工具集；API 自定义 schema 仍经过原生 schema 路径，不包装成可执行本地工具。

## 参考比较与最终采样

- 默认主请求以真实 PTY 交互 CLI 为基准；增加交互无工具和显式 system 场景。-p 默认、追加和替换样本保留为差异证据，不再充当目标基线。
- 原版 CLI、原版桥接、精简桥接使用相同固定版本、模型、合成账号类型和等价 HOME/config/cwd 内容。显式输入不能在两边偷偷换成不同设置。
- 逐字段比较 system、工具声明及描述、消息环境与提醒、默认模型参数、User-Agent、分类和关联。CCH 逐份对最终接收原文独立验证。
- 时间、随机 UUID、隔离目录路径和会话累计计数等动态字段列出逐项比较规则：验证格式、作用域及关联后，仅归一化明确的动态片段。prompt/tool 文本、静态 flags、thinking、safeguards、上下文管理等差异不得笼统忽略。
- 参考 CLI 的标题辅助请求单独计数；桥接每轮只允许一次实际模型请求，构造与本地初始化的发送数为 0。
- 最终样本复用现有 CaptureRecord/LogStore 结构，标明 isolated_local_tls 等真实接收来源。生产自动 wire_final 采集仍是未实现能力；页面全局能力状态和历史 SDK 样本保持真实，不改写历史或将 cc_prepared 冒充最终采样。

## 精简产物、兼容与回退

新增原生绑定同步 source-profile、preload、worker 接口校验、静态构建 definitions；新增桥接源码同步 build-runtime 的源码清单。精简闭包携带实际所需依赖，不复制整个终端 UI 或录制的默认提示词。

当前收敛的体积优化只保留四类明确边界：

- 固定 Vt 工具适配器的 create 只供本地 call、输入校验和权限执行。对从 permissions 模块导入的 Vt、顶层变量初始化的字面工具定义，将 create 方法体改为明确抛错，保留名称、schema、prompt、描述及可用性。非顶层、动态或未知形状不裁剪，不给未知工厂添加纯调用标记。
- 顶层 local/local-jsx 命令的 load/call 只进入终端本地执行。保留完整声明与可用性判断，仅阻断已核对的函数执行入口；prompt 技能保持原文。固定来源中符合条件的 55 个定义均无 spread 或重复 type，当前闭包实际包含 54 个 load 守卫。
- 固定两个模块的 He 原生附件加载调用明确抛错，不携带 audio-capture/clipboard-napi。这两个附件只提供终端音频或剪贴板输入，不参与结构化 API 消息输入及模型请求生成。
- 固定 Ze/Ztt/teo 资源读取器按魔数自动识别 zstd，也原生接受未压缩内容。构建时核验每份 .zst 原始摘要，以固定 Bun 无损解码为 UTF-8 原文后统一交给外层归档压缩，记录两种表示的长度及摘要。资源正文及官方读取器不裁剪。

## 具体风险

- 完整 CLI 工具和提示词装配可能扩大依赖闭包及初始化成本；需要先验证行为，再按现有压缩合同重新测量，不能为过体积/耗时门槛删掉目标 CLI 内容。
- 原生工具筛选、权限模式和提醒可能依赖会话或账号环境；需要以新根及同/异 session 多轮验证，避免默认池、缓存和父子状态串轮。
- 参考结果受模型、权限、功能门控和配置影响；参考侧与桥接侧需记录真实条件，未知分支明确失败，不能把一份录制结果当作所有 CLI 的固定模板。
