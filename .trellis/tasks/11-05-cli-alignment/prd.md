# 对齐固定293终端CLI的请求构造与出站行为

## Goal

以固定官方 2.1.293 交互终端 CLI 的真实请求构造与最终出站为基准，使桥接生成一致的 CLI 提示词、工具上下文和调用归因，保留结构化单轮调用、常驻隔离及部署体积预算，以可验证的安全与稳定为优先。

## Background

- 用户明确要求“我绝对要对齐的是cli”，并确认工具策略采用“显式列表完整替换，省略时使用默认工具”。先前只改变入口标识的实现不能满足这一目标。
- 开工基线 e68722f 中，src/runtime/293/job.ts:67 仍写入 turnOrigin=sdk，:96–97 固定 isNonInteractiveSession=true、hasAppendSystemPrompt=false，:81 只取业务 system，:87 使用空原生工具。src/control/header-policy.ts:71 的主来源仍为 sdk，src/control/engine.ts:208 还设置 SDK client-app，导致系统提示词和上下文保留 SDK 路径特征。
- 未修改原版的交互式 CLI 主请求实测为 CLI 身份、entrypoint=cli、turn_origin=human，初始声明 13 个工具，装配完整默认 system 和消息环境；另有独立的标题 auxiliary 请求。四种 -p 对照使用 SDK 身份或入口，不能将打印模式作为交互目标。条件、最终 TLS 样本及原始六份 CCH 校验见 research/cli-baseline.md 和 research/cli-baseline-summary.json；这些工具数量与正文长度不是通用常量。
- 固定来源、内嵌 Bun、原生 CCH、精简文件和常驻合同沿用 runtime-footprint 任务及 .trellis/spec/backend/runtime-contract.md。旧验收只证明旧适配器行为，不能替代本轮独立 CLI 对照。
- 2026-11-05 用户明确接受当前延迟，取消以 vm2api 速度为目标，要求安全优先。原三项 1.10 倍门槛不再作为本任务的验收条件；原始失败数据保留，不改称性能已修复。部署体积预算和请求正确性、凭据处理、隔离及单次发送约束继续有效。
- 随后用户明确确认“省略 tools 即无工具”，替换此前的 CLI 默认工具规则。当前桥接仅声明调用方显式提供的工具，省略与 [] 均不注入 CC 内置工具；CLI 提示词继续根据本轮实际工具生成。

## Requirements

- R1：以交互式终端 CLI 的原生装配为对齐目标；在同一固定官方 293、相同合成账号类型、模型、业务输入、实际工具选择及等价环境采集参考。API 省略 tools 的参考应禁用 CLI 工具，不再对照终端的缺省工具池。-p 行为单独作为差异证据，不作为默认目标。
- R2：复用官方 CLI 的默认系统提示词生成及上下文装配。省略 system 时使用原生 CLI 默认正文；用户已选择折中优化，允许复用从固定 293 原生逻辑取得、已证明不随会话变化的静态部分，动态上下文仍逐轮原生生成；不得将整份录制请求当作模板。显式 system 沿用业务正文替换语义，对应 CLI 的 --system-prompt，保留原生身份与归因，不静默改成追加模式。显式空字符串或空数组同样属于显式替换。不以手写身份句、覆写日志、强改版本或仅翻转入口标识充当 CLI 对齐。
- R3：消息来源、querySource、requestClass、session/prompt、agent/parent、metadata 与 billing 按实际 CLI 上下文关联。主会话、子代理、workflow、compaction、auxiliary、side_reply 保持各自类别；工具结果不伪装为新的人类输入，逐项说明与普通 CLI 基线的适用边界。
- R4：仅声明调用方显式提供的工具：省略 tools 与显式 [] 均表示无工具；非空列表完整采用调用方定义，不叠加 CC 内置、延迟、搜索或占位工具。提示词和工具上下文与本轮实际工具集一致，保留工具/thinking 历史。继续单轮返回原始响应与 tool_use，由调用方处理工具；无论上游是否返回声明外的工具，均不自动在本机执行。
- R5：继续使用实际原生 SDK/发送链路及 CCH，attempt=1，响应字节、流/非流、错误、取消及秘密处理合同不退化。最终采样来自真实观测点，标明本机接收端与生产自动采集的区别；缺失、截断及失败可见。
- R6：原版和精简版使用同一 CLI 适配合同；来源与执行身份分别验证，未知来源、布局或无法保留的显式输入明确拒绝。产物变更后重新构建、登记及验收，不覆盖原版或其它项目。
- R7：保留单账号常驻串行、每轮新原生根、故障退役且不重放。完整运行时部署文件总量继续不超过 27933052 B。保留启动至首轮、就绪后首轮、暖复用的实测及计时边界，原生本地初始化计入启动；用户已接受当前延迟，不再要求达到 vm2api 的相对速度，不为追求该指标绕过原生装配或共享可变会话状态。
- R8：全部研究、回归与最终采样使用独立 HOME/config/cwd、合成凭据和无外网回环；不读取真实账号、不触发真实登录、刷新或付费推理。官方源码、二进制及完整默认提示词不提交到 Git，原始采样留在被忽略的 artifacts。
- R9：桥接保留单轮执行边界，对齐本轮 CLI 请求构造，不引入终端 UI 的标题、建议等额外模型调用；参考 CLI 自身的辅助请求单独记录并分类。

## Acceptance Criteria

- [x] A1：已保存固定官方交互式 CLI 与四种 -p 对照的最终 TLS 基线及差异，包含命令、环境、来源身份、主/辅助请求计数及观察位置；九次参考启动的十四份 CCH 均核验通过，真实上游请求为 0；对应 R1、R8。
- [x] A2：以匹配实际工具选择的原版 CLI 验证默认系统提示词、工具声明及业务 system；省略 tools 和 [] 均无工具，非空自定义列表逐字段一致，三者均不得混入 CC 默认工具。普通主请求不出现 Agent SDK 身份前缀；对应 R2、R4。
- [x] A3：实际出站头部、metadata、billing、消息来源与六类上下文一致，动态字段按公开的比较规则分别验证，不笼统删除差异；对应 R3、R5。
- [x] A4：原版与精简版分别通过现有受支持场景及本轮工具默认值对照，每份最终正文独立验证 CCH；真实上游请求为 0、本地每轮模型发送符合 attempt=1，构造/初始化不发送，工具不在本机执行；对应 R4–R6、R8、R9。
- [x] A5：同 PID 多轮、相同/交替 session、取消/崩溃/迟到输出后的隔离与重建不退化；对应 R7。
- [x] A6：最终精简产物有完整构建及身份清单，部署文件总量符合预算，保留三项耗时实测和历史对照；用户接受当前延迟，安全与兼容证据必须覆盖本轮新哈希，不复用其它产物的验收结论；对应 R6、R7。
- [x] A7：日志页面能展示本轮 CLI 实际最终采样和明确来源，不改写既有 SDK 历史；文档明确单轮、显式输入和最终采集能力边界；对应 R2、R5、R8。

## Non-Goals

- 不接入真实账号或生产，不升级源版本，不替换未经验证的原生内核。
- 不扩展为在本机自动执行工具的完整多轮代理，不增加账号池或并发调度。
- 不复刻终端 UI，也不额外发起标题或建议等后台模型请求。
- 不在本轮增加生产自动 wire_final 采集能力；本机最终 TLS 样本与生产能力分别说明。
- 不继续以 vm2api 相对速度为优化目标，不采用未经完整回归的首发消费裁剪或录制请求模板；原生兼容及 CCH 证据不构成账号免封承诺。
