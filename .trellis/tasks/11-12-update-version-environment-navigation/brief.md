# Brief — 管理后台版本、环境导航与请求记录整理

## Goal

让平台版本易读、环境入口独立，并按 vm2api 的样式与交互整理请求记录及采集控制。

## Scope

- 平台版本从 v1.0.0 起步，修复递增补丁版本，功能递增次版本；时间显示浏览者本地时间与时区。
- 更新列表默认突出当前与最新版本，历史折叠，同一列表只展开一个详情。
- 顶部独立“环境”和“任务”入口，兼容原深链接、筛选、刷新及前进后退。
- 请求列表采用紧凑布局；详情分为概览、请求链路、性能、原始数据。
- 环境卡片增加账号级“请求内容采集”开关；请求详情直达对应环境，采集关闭、排队、成功、失败、丢弃、缺失及过期分别显示。
- 父任务负责共享样式、时间工具和联合验收；三个子任务依次完成导航、请求记录及开关、版本更新页。

## Non-Goals

- 本轮聚焦上述管理页面；其它业务页面和品牌沿用现有功能。
- 真实账号的采集选择由管理员通过开关管理。

## Technical Overview

- 前端构建与已签名发行说明使用同一版本来源；技术详情保留原发行编号与安装校验身份，旧发行展示历史构建日期。
- 采集切换校验账号归属、环境代次和配置版本，按空闲维护流程应用；忙碌或状态过期返回明确冲突，应用失败显示实际状态并恢复或进入对账。

## Context & Decisions

- vm2api 已有实际渲染截图与样式取样；沿用顶部导航及已有主题偏好。
- 内容采集与 debug 日志模式分别配置；开关影响后续请求，历史记录保持当时状态。
- 原请求成功且采集关闭；详情应按实际采集状态提供入口。

## Risks

- 采集切换涉及发送器重配，需验证失败恢复及身份、资源、内核保留。
- 目标文件含其它会话的采集改动，实施及提交需按实际片段适配。

## Acceptance

- 桌面和 390px 页面可用；详情支持键盘关闭、焦点返回及异步归属隔离。
- 两个时区正确显示同一时间；版本折叠与旧格式兼容通过回归。
- 采集关闭时文件读取次数为零；不同账号独立切换，忙碌及过期操作明确拒绝。
- 原认证、签名、维护门禁、脱敏及单次发送合同通过回归；验证使用合成数据，主动付费模型调用为零。

## Next Step

启动父任务并进入实现路由，先完成共享样式与时间格式化基础。
