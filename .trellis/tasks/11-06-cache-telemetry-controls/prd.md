# 可选缓存断点策略与遥测控制

## Goal

让操作者按需选择消息缓存断点策略和原生遥测状态，同时保持默认原生 CC 请求保真及单次发送行为。

## Background

- 用户确认采用上一轮建议：借鉴 cc2api 的 sub2api 选点、原生 CC 默认保真、遥测可配置且默认关闭。
- 当前业务基线为 64e74d11dead9034687f1268643ad235bc066219，官方运行时固定 2.1.293。已有未跟踪的 .codex/hooks/__pycache__/ 内容不属于任务。
- cc2api 参考提交为 47e75ef4a1e982e2693edab81d5387eedb6adf40；选点位于 src/service/rewriter.rs:4695，清除消息断点发生在 :3903，新断点 TTL 位于 :6002。
- vm2api 参考提交为 e0fbed172c40721bd68d7d9d5d8a53a4205b1e0c；seed-policy.mjs:19、:173 的实际默认值为关闭遥测。完整原生进程的离线开关对照已记录于 artifacts/vm-cache-telemetry-20261106/。

## Requirements

- R1：默认配置保持当前原生 CC 缓存标记、TTL、scope、消息顺序及省略状态；不因升级自动启用缓存改写。
- R2：提供显式选择的 sub2api 消息断点策略，使用尾部及倒数第二条 user 消息的可缓存块；调用方已有消息标记、根自动缓存或不可明确处理的形态保持原布局，并说明原因。新标记遵守预算及前置 TTL 顺序，不破坏业务正文或原生最终 CCH。
- R3：提供原生运行时遥测开关，默认关闭；开启必须对应固定运行时真实可达的采集及发送链路，并区分配置、实际初始化和原生策略抑制状态。
- R4：配置由本机操作者提供，不能从模型请求正文、扩展头或宿主账号状态隐式启用；沿用启动配置及重建引擎的生效方式，旧产物缺少显式选项的支持能力时失败。
- R5：日志能区分调用方原始入站与策略处理后的中间正文；已有 wire_final 未采集语义、脱敏规则和历史记录兼容性继续有效。
- R6：原版和精简运行时都以合成身份、独立 HOME/config 及离线回环验证；模型请求单次发送，真实上游请求数为零。

## Acceptance Criteria

- [x] AC1 / R1：省略全部新增配置时，现有 API 与原生场景的行为保持一致，原生正文差异仍限于既有账号归属及 CCH 占位处理。
- [x] AC2 / R2、R5：开启缓存策略后，短历史、长历史、现有断点、工具结果、thinking、断点预算和混合 TTL 场景有可检查的入站及出站样本。
- [x] AC3 / R3：同一隔离场景下，关闭遥测无上传；开启后可由本地接收器证明固定 293 原生发送路径被触发，失败状态及退出行为明确。
- [x] AC4 / R4：非法配置启动失败；调用方正文或头部不能覆盖两项控制配置；重建引擎后按新配置生效。
- [x] AC5 / R5：实际策略与日志说明一致，原有详情可读取，最终采集能力不被中间值替代。
- [x] AC6 / R6：两个子任务各自通过针对性验证；最终通过类型检查、构建、单元/集成、原版与精简原生回归及必要页面回归。

## Non-Goals

- 不复制 vm2api 的图片删除、system/billing 重排、模拟遥测或其他身份改写。
- 不实现会话级缓存主线存储、实际付费缓存命中率实验或防封效果承诺。
- 不添加页面管理开关、逐请求策略覆盖或运行中的热切换。
- 不把客户端遥测请求转发、第三方监控导出或遥测内容伪造纳入本轮。
