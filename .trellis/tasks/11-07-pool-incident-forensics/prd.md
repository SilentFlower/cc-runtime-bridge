# 断连现场自动取证

## Goal

本地池请求失败时自动保留可核验、已脱敏的现场证据，便于在下一次断连后定位问题，同时不额外发起模型调用。

## Background

- 用户已同意推进“失败请求 ID、发送阶段、错误码、连接计数、TLS 采集状态及可取得的代理／上游标识”的自动汇总。
- `src/shared/contracts.ts:127` 定义请求与采集状态；`scripts/testing/local-pool-ledger.ts:33` 保存可用传输回执。历史失败 `7fed8355-6c41-4f92-8700-db73a98ad3de` 缺少新增诊断，根因仍未确认；不能从后续成功实验反推旧请求原因。
- `src/control/log-writer.ts:56` 将正文与元数据分开存放，允许仅基于脱敏元数据取证。现有证据、时序及标识来源集中记录于 `research/findings.md`。

## Requirements

- R1 自动取证：手工本地池服务运行期间，对 error、http_error、stream_error、incomplete 终态自动生成独立报告；正常取消不自动报故障。支持按明确运行轮次与请求 ID 补采尚有记录的历史失败。
- R2 现场摘要：报告包含运行／请求身份、请求时间及终态、本地与上游状态、白名单失败码、发送阶段、发送事件观测、关联连接累计读写字节，以及各采集阶段的完整性和来源；记录状态与正文文件是否仍在分别说明。
- R3 外部关联：仅提取现有证据中可校验的请求／追踪标识，并注明来源；没有、损坏或互相矛盾的证据明确显示未知或冲突。
- R4 归属与去重：不同运行轮次、并发请求、排队请求和重启后的记录不得串联；重复扫描不重复生成同一请求报告。报告冻结采集时证据，补采使用新输出位置；部分采集、日志不可读或记录缺失必须可见。
- R5 数据与费用边界：只读现有本地记录，采集不调用模型、不重放或重试请求；报告不保存凭据、提示词、响应正文、完整头部或任意异常原文。
- R6 故障隔离：取证读取、校验、扫描或落盘失败不改变业务请求结果；取证自身状态可查，停止服务时收口取证活动。尊重原日志等级，日志关闭或存在写入缺口时明确显示不能取得完整证据。

## Acceptance Criteria

- [x] AC1（R1、R2）：离线制造连接断开及 HTTP／流失败后，自动得到与原请求 ID 一致的报告，保留已有诊断；明确 TLS 完整仅证明本地第一段实收，发送事件／连接计数不证明池端接收或执行。
- [x] AC2（R2、R3）：旧账本、缺少 TLS／响应头／标识、损坏诊断或冲突标识均得到明确的未知、失败或冲突状态，不编造根因。
- [x] AC3（R4）：覆盖多页扫描、旧请求晚完成、重复扫描、多个请求与服务重启；报告不串轮次、不串请求、不因只追踪创建时间而遗漏晚完成请求。
- [x] AC4（R5）：验证取证仅执行只读访问，模型调用／预算计数为零增量；植入合成秘密后报告和取证日志无秘密、正文或任意异常内容。
- [x] AC5（R6）：日志、账本、目录与写盘故障，以及日志关闭／缺口均可观测；业务请求终态及重试策略保持原有行为，关闭后无后台取证活动遗留。
- [x] AC6（R1、R4）：按运行轮次和请求 ID 补采历史记录能生成报告，来源轮次不匹配时拒绝拼接并说明缺口。

## Out of Scope

- 自动修复网络、自动重放、后台真实推理或新增真实调用预算。
- 根据本地发送进度断言池端收到、计费、执行情况，或为历史故障补造缺失诊断。
- 查询外部代理／池端日志、修改真实凭据或受保护配置、数据库结构迁移、修改转发协议和重试策略。
- 本轮不增加日志页面交互或完整原始请求导出功能。
- 自动改写已发布报告，或保证强制杀进程、日志关闭、过期／丢失情况下仍能取得完整现场。
