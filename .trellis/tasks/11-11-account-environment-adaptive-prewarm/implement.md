# 实施与验证

1. 冻结 bridge、bench、cc2api 的基线和文件归属。读取账号环境、调度、sender 池及联合部署规范。
2. 在 bench 接入显式账号策略和启动阶段的有界环境准备，验证容量已满时保持其他环境、启动时继续接受已有业务、手工停止后无循环唤醒。
3. 在 cc2api sender 池接入第二 worker 的同代次后台补位和等待协调，保留空闲回收规则。记录准备阶段、状态和耗时摘要。
4. 在合成凭据和回环上游中验证真实 worker 握手、首条复用、首条转发不受第二个握手阻塞、第二条提前/迟到的两种竞态、原回收期限、失败和代次隔离。确认预热阶段零模型调用。运行受影响的 Python 和 Rust 回归。
5. 完成 Check-All 与联合交付核对。生产按既有操作单只灰度 `11-5`；观察用户自然请求，沿原流程停用或回退。
