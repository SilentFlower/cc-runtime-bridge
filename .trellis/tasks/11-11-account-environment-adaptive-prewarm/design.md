# 技术设计

## 环境预启动

- bench 复用 orchestrator 启动生命周期，在已有对账与基础服务就绪后提交一次有界后台准备。按已有部署侧约定选择显式账号，默认关闭；使用稳定账号 ID 和唯一 V3 绑定核对启用状态、原生后端及维护状态。
- 复用 `AccountRuntime.ensure(..., require_quota_mount=False)` 和原网关预热入口。后台准备只使用可用容量，遇满跳过，不能调用主动回收其他账号的腾挪分支。准备、维护与业务共享现有环境锁。复用既有 readiness 与限次启动补偿；超出启动期后不定时唤醒账号。
- 配置为按账号启用的部署策略，默认空；bench 和 sender 从同批配置获取策略。该策略不改变账号身份、运行时制品或新旧客户端的业务协议；停用后沿用原行为。

## 预热第二个 worker

- 在现有 sender 池中，当账号允许两条普通并发且只有一个物理进程时，由首个业务 checkout 发起一次零模型补位。保留首条请求的独立响应路径。已经有可用或启动中的第二个时，禁止额外启动第三个。
- 背景任务只持有启动所需的账号身份和配置。启动使用既有物理许可、映像复用和真实握手。用同代次的单个启动登记处理竞争：后续请求优先取空闲 worker；若本轮补位正在启动，允许在自身期限内等到就绪或失败后沿原 checkout 决策。不能跨账号、代次或凭据状态移交。
- 归还及补位就绪继续进入现有 idle 集合和回收器。保持约 60 秒回收多余空闲 worker。关闭、维护和身份变更通过现有代次及取消语义清理后台资源。
- 使用当前安全日志摘要区分环境准备和 worker 补位结果。背景准备不带业务正文或模型作业指令。

## 回退

- 清空试点配置即可恢复原生命周期与单 worker 预热；部署按联合镜像流程回退。现有容器停止和容量回收策略仍可执行。
