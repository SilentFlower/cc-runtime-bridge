# 统一平台在线更新与兼容回退改造

## 目标与用户价值

让管理员从统一平台页面完成系统版本检查、更新和回退，减少每次变更后人工打包、传包和执行部署命令的操作。发布端统一生产可验证制品，部署实例获取并应用指定版本。

## 背景

- 现有内核已具备在线切换与回滚能力，平台包含网关、调度器、管理页面及账号运行环境。
- 现有 CI 自动发布 control/account 两类镜像；当前人工部署承担取包、检查、切换和收尾。
- 账号角色容器与发送端绑定包含整批发布号，平台更新复用既有环境需要明确兼容边界。

## 需求

- R1：提供平台级系统更新入口，展示当前版本、可用版本、变更范围及兼容条件。
- R2：更新采用发布端统一构建的制品，管理员通过页面发起更新并查看持久化进度及结果。
- R3：更新覆盖受信制品校验、运行状态检查、在途任务收口、健康验收及失败恢复。
- R4：明确平台版本、账号环境版本和内核版本的兼容关系，保留账号身份、凭据归属及资源设置。
- R5：页面展示当前版本的回退条件、可用目标和阻断原因，数据库及凭据迁移需要明确可逆边界。
- R6：沿用管理员鉴权与用户要求的现有管理页面样式；测试默认使用合成凭据与离线回环验证。
- R7：完整方案覆盖平台控制服务、账号运行环境与已有内核更新入口，按依赖分阶段交付，分别展示所选版本和实际运行版本。
- R8：保留当前版本、最近两个完整历史批次及所有运行实例和恢复操作引用的制品，健康验收后执行有归属依据的定向清理。
- R9：第一版采用用户已确认的维护窗口模式：暂停新接单，等待在途任务自然结束，再执行短暂维护切换。下载与准备期间继续提供现行服务。
- R10：自动检查并提示新版本，由管理员点击安装。安装请求冻结目标版本、制品摘要、现场版本和等待期限；重复点击与迟到请求按同一操作身份校验。

## 约束

- 当前 US 部署沿用用户此前确定的资源配置与免备份运维选择。更新设计需要明确在这些条件下允许执行的迁移范围。
- 用户要求等待另一批新构建完成后统一部署。当前部署保持暂停，恢复部署由后续明确指令决定。
- 排空阶段同时检查 API 请求、CLI/Pi 任务及执行意图。未知活动进入等待或人工对账。
- 排空超时保留原版本，按维护归属释放可安全释放的门禁并报告超时；门禁状态不明确时进入恢复流程。
- 账号身份、凭据归属和环境代次的校验继续有效，版本兼容检查需要独立于实例归属校验。

## 验收标准

- A1（R1、R2）：管理员完成检查版本、查看更新内容、发起更新、刷新页面后继续查看状态的完整路径。
- A2（R3）：下载或校验失败时，现行服务继续可用；执行进程或平台重启后能恢复操作状态。
- A3（R3、R5）：健康检查失败时按声明的兼容条件恢复上一可用版本，页面给出具体结果与恢复指引。
- A4（R4）：平台更新后账号身份、凭据单一所有权和资源配置保持一致，在途工作按已确认策略收口。
- A5（R5）：存在不可逆迁移时，在执行前明确回退限制并阻止不兼容的回退请求。
- A6（R6）：桌面与移动端的系统更新页遵循现有管理页面视觉规范，权限错误与版本冲突均有明确提示。
- A7（R4、R7）：更新页能区分平台、账号环境和内核更新；仅控制服务变化且兼容条件满足时，既有账号环境继续复用，容器 ID、账号身份和环境代次保持一致。
- A8（R8）：完成更新后，页面可查看历史及清理结果，所有受保护的镜像和内核制品继续可用于恢复。
- A9（R9）：下载准备阶段可正常接单；进入排空阶段后，新工作收到明确维护状态，在途工作自然结束后才开始切换，更新验收完成后恢复接单。
- A10（R10）：自动检查仅更新版本提示；安装由管理员点击触发。重复提交返回原操作，参数变化或现场版本变化返回冲突。

## 交付范围与后续范围

- 本轮交付为一台 V3 部署的系统在线更新完整闭环，发行合同、兼容校验、执行服务及页面作为同一交付联合验收。
- 零停机持续接单、多机滚动更新、定时自动安装及更新服务自更新列为后续范围。
- 第一版页面安装仅接纳经过兼容验证、旧版可读取并继续写入升级后数据的发行组合。不可逆迁移作为专门维护事项提示与阻断。
- 本轮包含首次接入工具与操作说明，生产接入和当前暂停的部署由后续明确部署指令执行。
