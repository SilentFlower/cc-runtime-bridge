# Brief — 修复实际Claude Code请求归因与代理关联

## Goal

- 修正实际 CLI 请求归类，并让子代理关联信息有证据、可追溯、缺失可见。

## Scope

- 自动权限分类归类、子代理父子及类型关联、证据持久化、日志 API 与页面展示。

## Non-Goals

- 原始网络断连、分类计费、修改用户 CLI、新增付费测试、重写历史采集，以及保证恢复没有证据的完整代理树。

## Technical Overview

- 按固定 293 的多项原生构造证据识别分类调用，使用 auxiliary / auto_mode；从匹配的 Agent 启动记录生成同会话代理关联视图，标明来源。

## Context & Decisions

- 已从实际样本找回这次 Explore 子代理的关联；分类提示词存在动态权限规则，不能只按整份哈希识别。
- 显式信息优先；后到证据只补充日志视图，保留发生时上下文及实际发送值。缺失、冲突或证据不完整时明确展示，类型未知不冒充自定义代理。

## Risks

- 证据可能缺失或过期；关联不能保证完整。分类识别必须避免把普通对话或局部特征当作分类调用。

## Acceptance

- 实际 CLI 的分类调用归类正确，子代理完成报告回传后能显示有证据的父代理和 Explore 类型。
- 普通请求、迟到证据、多层代理、跨会话、冲突、重启、清理和旧记录验证通过；业务正文、头部及 SHA/CCH 保持，每入站只发送一次。
- 类型检查、相关自动测试及桌面/手机页面通过；使用离线回环和合成凭据，新增真实模型调用为 0。

## Next Step

- 确认后启动本任务，进入实现路由。
