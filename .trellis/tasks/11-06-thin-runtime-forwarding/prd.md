# 收敛薄桥接职责并修复原生请求误拦与超时

## 目标

让 cc-runtime-bridge 作为 cc2api 后方的薄运行时桥接，保留原生发送和取消能力，把业务参数、调用预算及准入策略交给前置服务和实际上游。

## 背景与证据

- 用户明确要求移除桥接层重复的模型参数限制、固定请求总超时、2 MiB 请求门槛和 16 个作业门槛，并检查实际客户端联调问题。
- 当前 main 为 b5740bc；上一轮已在工作区移除手工 max_tokens=32768 上限并启动 8787，本轮接续这些相关改动；尚未提交或推送。无关 Python 字节码缓存保留。
- 只读采样当前联调 run manual-native-20261106T091357Z：42 条记录，35 成功、4 个 HTTP 错误、2 次取消和 1 次构造错误。样本仍可能继续增加，不重放用户请求。
- 请求 4ebd39cc-ac68-42f6-b425-96f83355e806（子代理）、e5b047bf-13aa-4d4a-a4c0-0a4c4eb793be、e29d5c12-b577-48a1-95df-be54bcf34709 均约 30.1 秒返回本地 POOL_TIMEOUT；账本 upstreamStatus=null、outcome=timeout，最终 CCH 核验已通过。来源：scripts/testing/pool-forwarder.ts:70 的总计时器。

## 需求

### R1 模型参数策略交还前置与上游

- 本地不再根据输出数值范围、温度范围、thinking 类型或最小预算、工具名称规则和工具组合推断模型可接受性。
- 保留实际解析和原生组装所需的基本 JSON/字段结构检查；原生业务字段保持原值，不裁剪、不补工具、不替换上游错误。普通 API 的适配器仍须具备构造所需的结构，不扩展其全部字段映射能力。
- 普通 API 路径不能通过删掉保留检查静默丢失调用方显式字段。

### R2 不再附加默认请求总时限

- 正常桥接和手工池联调默认不再附加本层 30/45/90 秒总时限，也不因本层 HTTP 空闲设置提前中断等待及流式响应；正常完成、上游失败、调用方取消和服务关闭仍按实际信号收口。
- 客户端取消、排队取消及服务关闭仍能终止本地和池端工作，之后的新作业可继续执行。
- 有限自动验收仍使用显式测试预算，不把自动验收的付费保护应用于用户请求。

### R3 移除重复业务准入门槛

- 不再因正文超过 2 MiB 或已执行/等待作业达到 16 个而拒绝合法请求。
- 同步检查私有消息通道中的正文长度限制，避免仅移除 HTTP 门槛而在后续通道重新拒绝。
- 保持当前单账号、单 worker 串行执行；不把本轮变成并发引擎重构。
- 日志预览截断只影响观测，完整请求和响应继续转发。

### R4 原生分类调用可靠发送

- 原生正文只借用 SDK 种子的发送上下文，最终 system/messages 等仍来自原生输入；种子内容的无关保留断言不应阻断有效调用。
- 保留原生调用次数、账号/会话归属、协议结构和生命周期约束，不靠关闭最终采集核验或默认重试绕过问题。
- 使用合成分类场景离线定位并验证，不把真实分类提示词或用户会话复制进测试夹具，不重新调用真实池。

## 验收

- AC1：max_tokens=128000、原生 thinking 和工具配置保持原值到模拟池；不兼容参数由原生实际构造或池返回真实错误，桥接不自设模型能力门槛。
- AC2：模拟池延迟响应和持续流超过旧本地预算仍正常结束；客户端主动取消及服务关闭能收口，之后请求成功。
- AC3：超过 2 MiB 的合成原生请求完整到达模拟池；超过 16 个执行/排队请求不产生本地 queue_full，串行归属正确。
- AC4：合成 claude-sonnet-5 安全分类请求通过原生上下文构造和最终 TLS 核验；messages/system 与原始业务一致，单次发送。
- AC5：日志的完整/截断/缺失状态和原始哈希可辨；现有自动验收小预算继续成立；类型检查及受影响离线回归通过。
- AC6：验证后有序替换本轮 8787 实例，保留所有旧日志和 8791 只读报告，启动及健康检查不触发真实推理。

## 范围外

- 不修改 cc2api，不新增鉴权、限流或重试策略，不自动触发真实账号或付费推理。
- 不更改运行时来源版本或校验规则，不删除凭据隔离和本机控制配置边界。
- 不重做日志 UI、日志容量/保留策略或并发账号池；本轮交付源码与当前原版 293 联调实例，已发布的轻量运行时内嵌旧代码，不因源码修复自动更新。
- 不宣称本次解决 ECONNRESET 等尚无闭合证据的网络故障。
