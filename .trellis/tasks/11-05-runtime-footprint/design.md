# 轻量运行时与单账号常驻设计

## 目标与边界

沿用 PRD R1–R8，以固定官方 293 为来源，交付一份达到标杆体积的专用运行时，再把一次启动服务一轮请求改为单账号、同进程、串行多轮。两个改动共享原生兼容和最终性能验收，不能分别宣布任务完成。

体积边界与 vm2api 的 cli-node 一致：CC 执行体及其全部专属运行依赖。既有桥接控制面和两边各自的控制服务单列；构建时才需要的原版、提取目录和工具不是运行依赖，最终启动不得访问它们。原版回退为显式选择，不要求在轻量部署中常备一份原版。

## 已有依据与前置关卡

- 固定源码、Bun 构建 API、原生节和依赖探针详见 research/compact-feasibility.md；vm2api 对照详见 research/vm2api-init-comparison.md。
- 原内核基线使用原版自带的 Bun 1.4.3，通过 BUN_OPTIONS 运行构建脚本及 Bun.build，compile.executablePath 指向校验后的原版。BUN_BE_BUN 在此固定程序上未提供可用编译入口。
- 探针把应用区减至约 17.19 MiB，四个已核对原生节逐字节相同，所需 11 个接口可以导入。但普通 UPX 压缩的完整探针仍有 34217464 字节；仅 Hello World 的相同内核产物也有 29599364 字节。它们都未通过 A1，不能把后续计划描述为已达标。
- 官方文档中的实验性 trim 不能直接套用：该固定程序的 trim 探针没有缩小文件，不以构建无报错认定选项生效。
- 第一实施关卡处理可复核的压缩布局、依赖闭包、原生基底和启动方式。候选必须满足总量、独立启动、固定 293 来源、可追溯内核及实际执行身份要求；达不到则留存证据，停止后续业务集成，不能擅自更换源应用或改目标。
- 首轮实施准入失败见 research/footprint-admission.md：当时可执行接口探针为 32.63 MiB，BCJ2 仅归档为 29.75 MiB。后续 kernel-admission.md 记录 ICU 裁剪及内存加载通过准入；当前常驻实现及最终体积/速度验收见 research/acceptance.md。
- 用户已批准原生内核裁剪或调整 Bun 构建基底。先固定候选版本、revision、发布来源和 SHA256，检查固定源应用的真实原生接口，再用独立 TLS 上游核对原生发送和 CCH；不能补写 CCH 或模拟 FetchSession 来绕过缺失能力。实际内核差异进入产物清单，原生节一致性只作为基线比较证据，不再是唯一接纳条件。

## 构建与产物身份

新增准入候选见 research/kernel-admission.md：保留原版 Bun 1.4.3 原生代码，ICU 资源按桥接固定的 C.UTF-8 工作环境保留 root/en、字符与规范化数据、全部分词规则/字典；不提供通用 CLI 的全部 Intl locale 定制保证。以 BCJ2/LZMA2 及静态 C SDK 加载器单文件分发，校验解码载荷后经封存 memfd 原位执行，无磁盘展开副本。该选择必须通过默认 locale、Unicode 与原生请求回归，不能缩减现有正文支持。来源、外层文件、解码执行体分别登记身份。

1. 构建驱动先验证原版 SHA256，再检查 ELF、固定应用区及模块记录边界，按原始编码和 loader 提取到临时目录。未知布局、越界指针、重复路径、缺失或损坏资源均失败。
2. 精简入口只绑定现有 Re/Kc/K_t、yN/Ree、Nst、su，以及经过读取验证的 F/nEr/yLs/t_。原生适配公共合同独立于源码位于哪种容器，不能复制或手写替代原生正文构造与发送。
3. 构建显式闭合依赖：把固定源码的静态 import.meta.require 定位转换为编译器可解析的引用；核对 He 确实来自固定辅助模块后处理文本资源；经文件读取的资源以明确文件导入保留字节。所有转换受源哈希、命中位置及数量约束，不对任意字符串全局替换。审计残留的动态导入、路径读取和原生扩展，不能以 metafile 的空 imports 列表代替闭包证明。
4. 使用实际选定且已核对身份的 Bun 编译器和原生基底，禁用环境值内联及 dotenv/bunfig 等额外自动加载，保留函数名。内核裁剪选项须以最终可执行文件和实际接口验证是否生效；原生调用能力及当前支持输入全部保留，不重新生成重复的整套应用字节码，不伪造 Bun 运行版本。
5. 选择通过前置关卡的打包方式；工具或新增启动器的版本、源码/二进制 SHA256、参数和运行依赖纳入清单。若引入内存解包，必须证明无需完整磁盘展开副本，并分别记录分发文件与实际执行载荷身份；不能只记录外层启动器的哈希。
6. 最终文件大小使用文件系统 stat，不能使用 Bun.build 返回的中间 BuildArtifact.size。输出每项部署文件、总字节数、应用依赖摘要、原生节摘要、来源、构建配方和产物 SHA256；临时提取内容和多份中间可执行文件构建结束后清理。
7. src/runtime/profile.ts 仍以原版为来源身份，另登记通过完整回归的轻量产物身份和启动类型。外部清单只能提供核对信息，不能自行授信新二进制；未知文件、版本字符串相同但内容不同的文件一律拒绝。

## 运行时校验与回退

- 继续通过现有 CCRB_CLAUDE_BINARY 选择原版或已验证轻量产物，不增加账号切换接口。原版使用预加载入口，轻量产物使用内嵌入口，两者调用同一工作进程逻辑及原生适配。
- 完整 SHA256 在创建引擎及每次加载新工作进程时核验，并在校验前后检查文件未改变。正常复用前比较实际路径及设备号、inode、大小、mtime、ctime 等文件身份；变化时当前作业发送前明确失败并销毁工作进程。完整校验不能由只比较文件名或版本替代。
- 校验结果绑定具体工作进程代次及实际执行载荷；日志中的 binarySha256 为实际执行体的固定身份，来源 SHA256 和外层打包文件身份作为独立信息，不冒充执行体。
- 原版路径不被覆盖。回退通过显式选择原版并重建引擎完成，不因轻量启动或回归失败自动换回原版、演示或其它内核。

## 常驻生命周期

- 保留 BridgeService 的最多 16 项串行队列，每个 NativeEngine 最多一个工作进程。不增加并发槽位或跨账号进程池。
- 首个实际模型请求惰性启动工作进程；创建服务及日志查询只校验或读取已有状态，不初始化 CC、不触发账号刷新。启动就绪须完成模块绑定和 Nst 配置启用，不在模块导入前宣布可服务。
- Engine 增加 close(): Promise<void>。服务关闭先停止接收、取消作业并等待队列收口，再关闭常驻进程；DemoEngine 及测试夹具实现相同生命周期。
- 工作进程绑定创建引擎时的 HOME、配置目录、显式凭据来源、代理、CA 和 cwd。更换账号或显式配置必须关闭并重建引擎，不能按请求切换环境变量或把不同账号交给同一进程。
- 首轮配对基准发现，就绪后的首次本地构造仍有约 170 ms 的惰性初始化成本，超过标杆首轮目标。就绪前在隔离的初始化根调用同一原生构造器，发送前中止，不调用实际发送入口，不发模型请求、事件或业务日志；随后每轮继续建立全新业务根。该成本纳入启动至首轮完整完成的计时，不移动或放宽总启动验收边界。
- 正常路径为未启动 → 初始化 → 空闲 → 执行 → 清理 → 空闲。取消、协议错误、未收口异常或进程退出进入隔离/退出，下一轮可以重建；仅重建进程，不重放失败作业。

## 每轮状态隔离

读取固定状态定义后，使用 AsyncLocalStorage 绑定每轮新建的原生根会话。yLs 注册当前作用域读取器，F 返回当前根，nEr 复用账号 host 并创建新的请求、账本和会话状态；sessionId 按本轮上下文设置，再调用原生 t_。同一 sessionId 的相邻请求也建立不同根，不能仅依靠 t_ 切换 ID 清理状态。

每轮独立拥有 AbortController、Redactor、生成/发送计数、响应读取器、SDK 释放承诺、requestId、事件输出闭包及计时器。原生构造、SDK 调用和响应读取始终在同一异步作用域。迟到回调只能看到旧根；作业收口后的输出闭包拒绝继续发送，不改写新请求身份。

维持 K_t 构造后在实际发送前中止，再由 yN/Ree 唯一发送的现有路径，maxRetries=0。清理须释放响应、等待 SDK 收口并移除本轮监听器/计时器，之后才允许下一作业。取消默认销毁进程，保留现有强制终止宽限；不以“尽力 reset”继续使用未知状态。

该机制已通过 requestJournal/异步迟到回调探针及原版、精简版各 17 项 TLS 回归；完整 billing、metadata、工具及 thinking 隔离结果见 research/acceptance.md。发现无法隔离的已支持路径时不能删掉该路径以换取常驻验收。

## 私有协议

HTTP 请求/响应、外部 schema_version=1、RequestTrace 使用的 RuntimeEvent 保持现有语义。新增工作进程包装协议 schema_version=2，由 shared/contracts.ts 定义、shared/protocol.ts 严格解码，控制层解包后再生成现有 RuntimeEvent。

| 帧 | 必需字段与语义 |
| --- | --- |
| worker_ready | schema_version、worker_id、version、pid；完成固定接口及配置初始化后只发一次 |
| request_start | schema_version、worker_id、request_id、prepared；仅空闲进程接受，prepared 沿用现有 PreparedInput |
| request_cancel | schema_version、worker_id、request_id；仅取消完全匹配的当前作业 |
| request_event | schema_version、worker_id、request_id、payload；payload 为现有 RuntimePayload，attempt 仍为 1 |
| worker_idle | schema_version、worker_id、request_id；该作业终态输出和清理完成，可接收下一作业 |
| worker_shutdown | schema_version、worker_id；关闭控制管道并退出，不触发新请求 |

worker_id 为控制层每次启动生成的 UUID，贯穿该物理进程，request_id 沿用入站请求 ID。stdout 只传协议，stderr 持续排空且不原样落盘。

控制层保持一个进程读取循环，作业事件继续 await 消费者以保持背压。run 必须同时收到唯一作业终态和匹配的 worker_idle 才结束。重复握手、并发 start、错代次/错请求、终态后事件、畸形或超限帧均不能归入下一作业；判为协议故障并隔离进程。旧进程读取回调绑定旧代次，不能触达新进程的当前作业。

## 验证与度量

- 原版与候选分别执行现有无外网 TLS 原生套件，独立检查 CCH、头部、metadata、session/prompt、主子代理与压缩身份、工具/thinking 历史、流/非流、HTTP/SSE 错误和取消；每轮实际上游请求必须为一次。
- 增加真实常驻 PID 多轮验证，以及伪进程故障验证：同 session 不同 prompt、交替 session 与请求类别、迟到事件、双终态、缺 idle、初始化失败、流中断、取消、文件替换、关闭和背压。合成账号秘密不能进入持久日志。
- 最终独立部署目录不得依赖提取目录、构建工具或原版程序；核对依赖清单和运行生成文件。磁盘量与 RSS 分开报告，内存解包不能冒充内存节省。
- 与固定 vm2api 交错顺序各运行至少五个新进程，每进程至少六轮串行作业；同一模拟上游、输入语义、输出负载和隔离环境，原版只作兼容及辅助性能对照。
- 直接记录从启动到首轮完整返回、worker_ready 到首轮完成、后续复用作业的原始样本和中位数，不能相加不同中位数冒充首轮总时间。记录页缓存未清理、RSS、后台负载、额外磁盘/内存文件及请求次数；正式计时期间不并行压缩。
- 两边均从 CLI 运行时作业协议计时，不把本项目 HTTP/日志链路与 vm2api 裸 CLI 混作同一指标；控制面额外耗时另列并确认无逐轮全文件读取或重启。

## 风险与停止条件

早期普通同内核编译加 UPX 未达标，未被接纳为最终路线。当前固定原生代码、ICU 裁剪、BCJ2 内存加载及异步状态隔离已用最终产物验证；结果见 research/acceptance.md。任何一项硬性验收失败均保持任务未完成，记录证据并反馈，不能用版本伪装、丢资源、降低兼容范围或漏算依赖过关。
