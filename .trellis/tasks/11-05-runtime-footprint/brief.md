# Brief — 对齐 vm2api 的运行时体积与速度并支持常驻复用

## Goal

- 保留官方 293 原生请求行为，使完整运行时的磁盘体积和处理速度达到 vm2api 水平，并支持单账号常驻串行复用。

## Scope

- 轻量构建、产物身份校验与原版回退入口。
- 常驻进程生命周期、每轮请求隔离、取消与故障恢复。
- 部署体积清单、原生回归及同机性能对照。

## Non-Goals

- 不接生产、真实 OAuth、多账号或并发调度。
- 不升级 293，不改写原生请求和发送语义，不提交官方程序或提取源码。

## Technical Overview

- 从固定 293 源应用生成专用构建，允许裁剪内核或调整可追溯 Bun 基底，先通过原生兼容及体积准入，再接入常驻工作进程。每轮建立独立原生会话根和取消状态；故障时销毁进程，下一轮重建，不重放当前请求。

## Context & Decisions

- 主要改造 engine.ts、293/preload.ts 及私有协议；首轮请求惰性启动，正常请求复用同一进程，日志查询不初始化 CC。
- 新进程加载时核验完整哈希，复用前检查文件身份；来源、打包文件和实际执行体的身份分别记录。
- 体积按与 vm2api CLI 相同边界统计，全部新增运行依赖计入；体积准入失败时保留证据并反馈，暂不开展后续业务集成。

## Risks

- 最终完整文件 25.18 MiB；五次配对的总启动、首轮和暖复用均通过原定门槛，原版及精简版各 17 项原生回归通过。证据见 research/acceptance.md。
- 保留原版 Bun 1.4.3 原生代码，ICU locale 按固定 root/en 环境裁剪；当前正文/Unicode 行为已验证，不作为完整通用 CLI 的全部 Intl 定制支持。
- 内存展开约 102.25 MiB，RSS 与磁盘空间分开报告；离线合成数据不代表真实模型、OAuth 或生产性能。

## Acceptance

- 完整运行时必需部署文件总量不超过 27933052 字节（26.64 MiB），额外运行空间单列。
- 至少五次同机配对测试中，启动至首轮完成、就绪后首轮及复用请求的中位耗时均不超过 vm2api 的 1.10 倍；采用相同本地合成上游，不当作真实模型速度。
- 通过原生 TLS 回归，独立核对 CCH、头部、上下文、工具/thinking、流式与非流式及每轮单次发送。
- 正常多轮使用同一 PID，会话、主子代理和压缩请求不串状态；取消、断流和迟到帧不污染下一轮，不触发重放。
- 构建可重复核验，未知或损坏产物明确失败，日志身份真实，原版可显式回退；验证只使用独立 HOME、合成凭据和无外网回环。
