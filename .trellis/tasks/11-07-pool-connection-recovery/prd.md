# 定位并修复池连接异常

## 目标

在每入站最多一次模型发送的边界内定位池连接失败，修复可复现的本地传输缺陷，并为不能当场归因的断连保留足够的安全证据。

## 已确认事实

- 父任务：`../11-07-transport-forwarding-repairs/prd.md`；研究与合成证据位于父任务 `research/`。
- 真实失败 `7fed8355-6c41-4f92-8700-db73a98ad3de` 为 UND_ERR_SOCKET；尚未收到池响应头，不能据此判断模型请求未发送。
- 离线 HTTPS 池读完整 POST 后主动断开可得到相同错误码，且当前客户端的下一独立请求成功；该实验不证明原始故障根因。
- `scripts/testing/pool-forwarder.ts:77` 已要求关闭连接，不能直接假设问题来自陈旧连接复用。现有账本丢弃 failureCode，也没有发送阶段证据。

## 需求

- R1：在无外网回环中区分建立连接失败、发送流程开始后断开、响应头后流中断，并验证每种情况的故障收口和下一独立请求。
- R2：按请求关联安全诊断，保留白名单错误码、最后观测阶段、可用的连接累计计数和池响应是否实际观测；缺失以 unknown/null 表示。
- R3：仅修复有同一回归场景和因果证据支持的本地传输问题；未定位原始故障保持未解决，不把增加诊断或独立回环通过当作消除断连。
- R4：不自动重试、重定向、换模型、绕过代理或延迟伪造成功；已经开始返回响应时不拼接伪造的成功或 SSE 终态。
- R5：诊断不保存 URL、原始异常 message、头、正文、凭据或私有 IPC；历史账本和旧日志继续可读。

## 验收条件

- [ ] AC1：离线故障矩阵分别覆盖直连、HTTP CONNECT 加 HTTPS、收头前断连与流中断；每场景均核对实际模拟池接收次数。
- [ ] AC2：没有池响应头时 upstreamStatus 为 null，本地状态单独记录；阶段和连接计数未知时不填零或推断成功。
- [ ] AC3：合成密钥不进入新诊断，观测功能失效不会改变正在转发的模型结果或触发重放。
- [ ] AC4：故障后下一独立请求、取消及关闭正常；有本地修复时保存修复前失败和修复后通过的同场景证据。
- [ ] AC5：原始断连若仍无归因，明确记录继续排查所缺证据，不将其标记为已修复。
- [ ] AC6：类型检查、诊断合同单测和离线池集成通过，真实模型自动调用为零。

## 范围外与依赖

- 不修改用户代理或上游池，不消除外部网络天然可能发生的断连，不新增付费验收。
- 不依赖头部子任务的实现顺序；最终整体回归需要合入其结果。该依赖由父任务执行计划管理。
