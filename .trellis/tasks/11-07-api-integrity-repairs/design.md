# 总体设计

## 边界

三个子任务按日志、轮次、参数顺序执行；父任务只维护来源映射与联合验收，不占用旧运输修复任务。子任务使用同一官方原版与现有 API/IPC/五阶段日志合同，不改数据库结构。

## 跨层流程

普通 API → 已验证上下文 → 同次 CLI 消息/参数构造 → 有界 disabled 参数保留与完整保留校验 → 同一 Ree 发送 → 可选 TLS 最终采样 → 事务日志快照 → 只读详情。完整原生 CC 入站沿现有保真分支，不应用普通 API 参数补齐。

## 关键决定

- thinking 只补明确且仅含 type=disabled 的对象被原生省略的情形；同时从实际 init.body 和 captured.body 反映补齐结果，CCH、身份、默认参数保持原生来源。其它不能表达的显式参数仍返回受控错误。
- Prompt ID 绑定本次请求里最近的实际用户轮次。显式 context.promptId 可跨工具调用和工具结果复用；省略继续按每请求生成，不以 sessionId 冒充 promptId，也不复用上一原生根。无可归属用户轮次的历史明确拒绝。
- 日志文件先准备，请求与阶段索引同一写事务；详情元数据同一同步读事务取出，随后异步读正文。采集能力与采集成功继续分别展示。

## 风险与回滚

上游可能不遵守 disabled，必须分别报告适配发送正确性与模型语义。续轮不完整历史会由模糊缺标识变为明确拒绝。事务必须覆盖所有阶段索引而不把异步文件读取放入事务。每个子任务独立回归，三项完成后统一生成按子任务分组的精确提交计划，失败时回退当前子任务范围，不回退旧脏文件或历史证据。
