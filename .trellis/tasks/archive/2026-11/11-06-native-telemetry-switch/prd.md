# 默认关闭的原生遥测开关

## Goal

让操作者显式控制固定 293 第一方遥测，并能验证关闭和开启的实际差异。

## Background

父任务为 11-06-cache-telemetry-controls；共享控制配置及 worker 能力握手以前一子任务 11-06-sub2api-cache-policy 的交付为基础。现状是 src/control/engine.ts:214–215 固定关闭，worker 没有调用官方第一方 logger 初始化；原生签名与模块证据见父任务 research/source-findings.md。

## Requirements

- T1：CCRB_TELEMETRY 接受 off/on，默认 off；非法值启动失败，改变后重建引擎生效，调用方不能覆盖。
- T2：off 阻止原生遥测采集和上传，包括本地初始化、常驻复用和关闭阶段；不读取或上传真实账号测试数据。
- T3：on 接入固定 293 官方第一方采集/发送，尊重原生账号、提供方和本地策略的抑制条件；不伪造事件、身份、进程指标或上传成功状态。
- T4：bootstrap 始终不产生遥测；on 仅在本地初始化收口后启用。遥测在后台处理，不延迟模型响应或触发模型重试；退出清理有界。
- T5：自动更新、错误上报及远程功能配置获取独立保持关闭；本轮不启用第三方监控 exporter。
- T6：配置状态与原生实际初始化/被策略抑制的状态可区分，初始化成功不冒充上传成功；旧精简产物不支持开启时明确失败。
- T7：原版、精简产物及与两种缓存策略的组合均通过隔离回环证明。

## Acceptance Criteria

- [x] TA1 / T1、T6：省略值、off/on、非法值、直接引擎调用和旧 worker 能力不足都有边界验证。
- [x] TA2 / T2、T4：关闭组从启动到退出遥测上传为零；bootstrap 没有模型请求及遥测事件。
- [x] TA3 / T3：开启组通过本地 CONNECT/TLS 接收器观察来自真实业务构造路径的官方原生事件及 metadata，身份属于独立合成配置；不使用自制事件代替该证明。
- [x] TA4 / T3、T6：原生策略抑制和初始化失败分别可辨认，不能把配置 on 当作上传成功。
- [x] TA5 / T4、T5：遥测接收器失败/超时、作业取消、worker 退役与服务关闭均有界，模型响应及单次发送不受影响；无自动更新、错误报告和第三方监控上传。
- [x] TA6 / T7：新精简产物双次构建和原生回归通过；缓存 preserve/sub2api 与遥测 off/on 四组合均有验证，真实上游访问为零。

## Non-Goals

- 不复制 vm2api 的受管 VmTelemetryOwner、模拟进程指标或手造 tengu_init/api_success。
- 不转发客户端遥测请求，不新增遥测公网目标或生产测试端点覆盖，不打开第三方 OTel。
- 不新增页面管理、逐请求开关、热切换或上传成功率面板。
- 不自动删除专用配置目录内既有遥测文件，也不绕过原生账号/组织策略。
