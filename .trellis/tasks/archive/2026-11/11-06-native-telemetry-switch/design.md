# 技术设计

## 1. 前置与复用

本子任务在缓存子任务的配置、worker 能力握手和 health 只读投影上增量接入。共享文件修改保留前一子任务成果，不引入平行配置解析器或第二套原生 host。

NativeBindings 的第一方导出从既有 context 模块增加 SLe/a4/MDs/bLe/Jk/gyr/Yus/Nco/w9t/gDn/tt，并绑定 chunk-nayw0pf7.js 的 G_o 事件接收器；实际签名已读取。完整 CLI sink 的 P8 同时涉及第三方通道和启动队列，本轮只把原生事件接入官方第一方采集器，保留原生采样及 metadata 脱敏。同步 source-profile.ts、native.ts、原版预加载及精简静态导出清单，避免两种运行时路径漂移。

沿用官方 sink 的同步重入保护，防止 model/betas/auth 元数据构造再次记录事件时递归。模型目录未就绪时先在后台等待 w9t，再以 gDn(tt()) 登记当前模型、由 Yus 脱敏后交给 Jk；不能在别名映射未准备好时上传原始模型名称。等待和采集失败只丢弃遥测，不阻塞业务响应。

第一方客户端还需绑定 chunk-19kr5wet.js 的 Jb() 官方网络初始化，使用引擎已有代理和 CA，不能把模型 FetchSession 的配置假定为第一方 HTTP 客户端已配置。原版回环证明在调用此入口后收到真实第一方事件，并确认走 CONNECT/TLS。

## 2. 环境与初始化时序

1. Engine 启动 worker 时仍设置 DISABLE_TELEMETRY=1、NONESSENTIAL=1、DISABLE_ERROR_REPORTING=1、DISABLE_AUTOUPDATER=1；通过专用控制值传递 off/on。
2. worker 校验配置，在 initializeCli 前注册按业务异步上下文筛选的原生事件接收器，丢弃原生启动队列及 bootstrap 事件；此阶段保持关闭，不初始化 logger。每轮结束撤销该作用域的采集许可，迟到回调不能变成下一轮事件。
3. off 直接维持关闭。on 在 bootstrap 收口后移除遥测专用关闭键，包括 NONESSENTIAL 和 DO_NOT_TRACK；保留自动更新、错误报告关闭键，显式关闭 GrowthBook 远程拉取，不导入第三方 OTel 初始化入口。
4. 读取官方 a4 判断资格。若受原生策略抑制，恢复关闭键并记录 suppressed；允许时先调用官方 Jb() 配置网络，再调用 SLe()，初始化成功才记录 initialized。发生异常按 native_configuration/503 终止启动，不回显原生秘密。
5. worker_ready 报告实际状态，随后接收业务作业；真实原生构造链负责产生事件及 metadata，桥接不另造事件。

固定 293 的关闭键采用存在性判断，开启不能写字符串 0。配置读取可能关联原生账号/提供方限制，不能修改这些限制来制造开启成功。

## 3. 状态与兼容

| 状态 | 含义 |
| --- | --- |
| off | 操作者关闭，不初始化或发送 |
| pending | 配置允许，但 worker 尚未初始化 |
| initialized | 官方 logger 已初始化，不代表服务端接收成功 |
| suppressed | 原生策略禁止，模型服务仍按原策略运行 |
| unavailable | demo 或旧产物没有该能力 |

状态类型集中在共享边界，由 worker_ready 校验后投影到 Engine 和 /api/health；不能由控制层凭环境猜 initialized。默认 off 兼容旧握手；显式 on 缺能力、缺状态或回显不符时失败，避免旧精简产物静默忽略。

本轮不增加上传成功计数或后台上传日志协议，不能以 initialized 替代真实上传结果。脱敏错误、配置与状态只包含控制枚举，不暴露凭据或完整身份。

## 4. 批处理与退出

- 使用原生 logger/exporter 的队列、批处理和第一方鉴权，不建立桥接自有队列或重试层。
- 仅跟踪最多 128 个尚未完成的官方 metadata 采集承诺，用于退出收口；这不是待发事件队列。同步/可等待原生事件都在后台采集，超限或采集错误丢弃遥测，不阻塞模型路径。
- 模型发送及响应读取不 await 遥测 flush，保持桥接独占原始模型响应，SDK 仍在首发后收口。
- 只有 on 且初始化成功时才调用官方退出入口；给予总计不超过 1000 ms 的清理预算，与控制层 1500 ms 进程宽限配合。超时结束进程，不等待额外网络活动。
- off 不调用初始化或退出上传；旧原生队列文件留在专用配置目录，不主动上传或删除。
- 任何遥测失败不能触发模型重放、影响下一作业归属或向 stdout 写普通日志。

## 5. 验证路线与构建

实施第一步用原版固定 293、当前桥接入口、独立合成账号及回环接收器证明自然产生的第一方事件能发送；不先假设仅增加环境变量即可。若没有该证明，先定位或调整实现，不能声明 on 可用。

接收器按域名区分模型、第一方遥测、其他网络请求，并保留脱敏头和有界正文；所有域名仅在无外网命名空间内转到本机，禁止真实账号/付费请求。复用已有 CONNECT/TLS 验证结构，不加入生产端点覆盖设置。

验证初始化前零遥测、off 全生命周期零上传、on 真实原生事件、策略抑制、网络失败及有界退出；同时记录模型请求数与原始响应字节。新导出可能增加精简闭包，重新构建并在 27933052 B 约束下核对双次结果、实际执行体及完整原生回归。

## 6. 回滚

CCRB_TELEMETRY=off 并重建服务。若新产物未完成能力和原生验证，保留旧登记与默认关闭行为，不发布半可用开关。
