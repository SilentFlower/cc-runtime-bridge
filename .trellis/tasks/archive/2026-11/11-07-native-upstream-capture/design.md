# 技术设计

## 方案调整与依据

原先“第一跳接收后，再由另一个原版 Ree 发送”的方案不能观察产品内的最后一次原生处理。原生诊断虽可输出最终 CCH，但复用连接缺少后续完整请求，无法作为可靠接口；原生 Messages 路径也未导出 TLS 密钥。

采用默认原版直连、可选可控 TLS 验证通道。验证模式最后一跳使用独立辅助程序及固定 293 画像，业务仍由原版生成。该通道在最后写出位置采集 HTTP 字节，不依赖第一跳推断最终值。它不是官方 TLS 实现；已做四组可行性对照，完整行为验收仍是交付门槛。

## 数据流

1. 启动侧校验、冻结端点、模型、凭据、代理及验证策略。
2. 保留入站原文；解析后只应用显式根模型覆盖，再进入现有上下文和 CC 构造。
3. 关闭：前置 → 原版 CC/Ree → 上游。
4. 开启：前置 → 原版 CC/Ree → 内置验证器的 TLS 接收端 → HTTP 原字节透传 → 固定画像 TLS 写出通道 → 同一上游。
5. 原生 CC 完成 CCH 后，HTTP 请求行、有序头和正文不再经过 fetch、HTTP 客户端、JSON 序列化或账号改写。
6. 响应沿同一连接原字节返回，原生 CC 继续负责 HTTP/压缩解析；桥接仍取得原始逻辑响应与既有终态。

## 配置合同

| 配置 | 落点及缺省 | 失败语义 |
| --- | --- | --- |
| `CCRB_NATIVE_BASE_URL` | 新增 EngineConfig.baseUrl；显式传入 ANTHROPIC_BASE_URL，缺省不传 | HTTP(S) 绝对地址，无 URL 凭据/query/fragment；保留原生 SDK 的路径语义，非法值启动失败 |
| `CCRB_MODEL_OVERRIDE` | 服务前置根模型覆盖；缺省保留请求模型 | 拒绝空值、控制字符和无法表达的参数，不回退 |
| `CCRB_TLS_CAPTURE=off\|verify` | 启动侧模式，默认 off | verify 只接受已验证运行时、HTTPS 和受支持组合；辅助程序缺失/身份不符明确失败，不换 Node 发送 |
| 现有 API Key/OAuth/代理/CA | 沿用专用入口，按实例固定 | 不从请求或宿主账号补齐，代理错误不绕行 |
| 本地 CC 入站策略 | 独立启动入口复用 NativeIngressPolicy，严格默认保持 | local_base_url 只决定入站兼容，不由请求授权，也不依赖旧池 TLS 模式 |

只读健康状态公开安全摘要及辅助程序身份，不公开凭据。网页不增加配置写入口。

## 原生请求与模型记录

- 解析后复制 BridgeInput，只覆盖根 body.model；不改入站原文、历史 model、业务 system、工具或关联证据。
- 发生时原始模型、有效模型和选择来源由集中合同定义，日志解码及页面统一消费。
- device_id/account_uuid 仍由同次内部 CC 生成，调用方 session/父子证据按现有合同保留。
- 分离入站兼容与受信任出站分支；内部使用自定义目标时，不再因旧补丁强制增加原生未生成的 CCH。
- 验证通道不计算或改写 billing；CCH 独立复算仅用于对照测试。

## 可选 TLS 辅助程序

- 增加独立小型 Rust 辅助程序，采用从 cc2api 研究得到的固定 293 画像及可追溯的 craftls/rustls 能力。生产必须独立固定源码、依赖锁、许可和构建身份，不能依赖外部 cc2api 工作目录或缓存 rlib。
- 不引入完整网关或 reqwest；不在验证器里重新创建 Messages 请求。辅助程序只负责限定目标的 CONNECT/TLS、双向原字节转发和采集。
- 验证开启时创建私有控制通道、本地临时 CA/服务端证书、监听器及进程；信任仅注入本实例，不修改系统证书库。
- 接入绑定实例/worker 代次及私有代理凭据；只接受冻结的 host/port，拒绝未知 CONNECT、普通代理转发和跨实例连接。
- Linux 回环 socket 还须在已核验 worker PID 的 TCP 表和文件描述符中确认实际所有权，防止退休代次或同实例其他进程仅凭旧代理凭据接入；检查失败关闭连接，不写出业务。
- 上游沿原配置使用代理及信任根，不回到本地捕获代理形成环路；未支持代理组合显式拒绝，不静默直连。
- 对上游代理的 CONNECT 继续沿用原版第一跳的原始行、头部顺序和 Proxy-Connection，仅移除本地代理凭据或替换为冻结的上游代理凭据；独立比对该握手，不只比较隧道内的 Messages。
- 一条 CC TLS 连接对应一条上游 TLS 连接；保持 HTTP 字节、背压、半关闭和错误，不增加独立 HTTP 连接池、强制 close、重试或总时限。
- 恢复策略按原版实测基线固定，不能因库默认支持恢复就额外启用。
- 首版验证范围为已登记的模型发送；遥测等使用其他传输画像的组合未验证前明确拒绝，正常直连的既有策略保持。
- 辅助程序与官方 CC 分别登记二进制身份及画像，不能以官方 SHA 冒充辅助程序身份。

## 最后一跳采集

- 采集在对上游的最终 TLS 写出通道，记录成功接受及刷出的 HTTP 原字节；只有接收端样本不能代替它。
- 同步增量计数/哈希及有界预览，记录实际写入范围、刷出状态、完整/部分状态。写出失败不能把待发送缓冲区整体记为已写出。
- HTTP 解析只用于旁路观测和绑定请求，不修改转发数据。实体、有序头、HTTP 版本及连接代次绑定当前 worker/request/attempt。
- 私有帧集中校验实例、代次、请求、连接、序号、字节数及完成状态；拒绝重复、迟到、错归属或不完整证据，不能回填到下一请求。
- 原始内容只在私有通道与有界内存流动；控制层先注册秘密再脱敏持久化。采集慢或失败必须可见，不触发模型重放。
- FinalCaptureSample 增加受信任来源/完整性语义。新来源表示最后一跳 TLS 本地写出明文，不称为加密网络帧，也不证明上游已接收或执行。
- 第一跳验证样本与旧池样本保留真实来源。off 时最终采集 unavailable，采集失败 failed；截断独立于模型终态。

## 验收门槛

- 独立上游对照固定原版与验证模式：完整公开 ClientHello、有序 cipher/扩展/公开载荷、签名、groups/versions、key_share、SNI、ALPN。
- 验证实际密钥交换、TLS1.2/1.3、HRR、证书拒绝、复用/关闭/重连及恢复策略；不能只测 JA3 或自造的 profile 对自身通过。
- 对照最后写出与上游实收的完整 HTTP 原字节，覆盖特殊字符、重复头、大正文、流、慢消费者、取消、错误与并发。
- 评审时原型仅完成 TLS 1.3、TLS 1.2、HRR、2 MiB 单连接测试及 8 条独立 CCH 核验，不能以原型替代产品验收；批准后的透明中继和生命周期结果见 research/acceptance.md。
- 不要求随机数、密钥、票据、TLS 实现代码或绝对时延相同。支持范围内出现差异必须修正或拒绝该组合，不降低测试标准。
- 原型曾因把 CA 当服务端叶证书而被 rustls 拒绝，已改为正常 CA+叶证书链。生产不关闭证书校验来凑通过，证书兼容差异必须记录。

## 发布与回滚边界

- 正常构建和验证辅助程序的构建分别可追溯；完整验证产物需在交付前构建并核验，release 体积及依赖纳入检查。
- 关闭验证不启动辅助程序，恢复原版直连；清除端点/模型覆盖恢复原生选择。
- 旧精简运行时未经重建验证不宣称具备新配置/采集能力；不静默替换文件。
- 历史日志及旧显式池验收工具保留原合同。实验使用独立端口/目录，不操作现有 8787 服务或真实凭据文件。
