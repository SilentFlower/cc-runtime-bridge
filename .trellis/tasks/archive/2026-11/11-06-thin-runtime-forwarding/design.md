# 设计：薄运行时桥接

## 职责与数据流

前置 cc2api 决定业务准入与预算，桥接解析必要结构并调用固定原生接口，上游决定实际模型参数能力。原生 HTTP 正文经身份归属准备、原生最终处理和 TLS 观测后，仅按既有池映射修改目标、根 model 与必要鉴权/传输字段。

保留单 worker 串行、唯一发送、取消传播、账号隔离、固定运行时身份和私有帧归属。移除业务策略不等于改为并发运行或执行请求中声明的工具。

## 参数入口

- src/shared/input.ts 保留对象/数组/文本等组装所需结构，数字需要可表示为 JSON 数值；移除 max_tokens 正数/整数范围、temperature 0–1、thinking 枚举和 1024 下限，以及工具名称/组合的模型政策。
- src/shared/parameters.ts 的 validateToolChoice 不再作为两类业务请求的模型能力门槛；删除无调用的辅助函数及对应旧政策断言，改用原值传递回归。
- 原生输入的 tools、tool_choice、thinking、output_config 和扩展 JSON 不经普通 API 重组；普通 API 仍须满足实际原生装配的必要结构，并保留 ensureSubset/ensureMessages 防止显式字段悄悄丢失。

## 原生上下文种子

generateNativeRequest 新增内部用途参数 purpose，类型为 'business' | 'transport_context'，默认 business。它只由内部调用方选择，不进入 HTTP 或私有作业合同。

- business：用于普通 API 和本地 bootstrap，继续验证业务历史、同次原生提醒和显式字段保留。
- transport_context：仅用于 runNativeJob 的原生分支种子，不把即将丢弃的种子历史当作最终业务正文做保留断言。
- 两种用途都要求真实 SDK 生成合法 JSON/头和发送上下文，只进入一次 fetchOverride，不执行工具，不重试模型；缺少上下文或非法结构仍明确失败。
- 原生分支在该回调中 prepareNativeBody、应用已选择的缓存策略，再由同一原生发送链路完成最终处理。原始业务 system/messages 不被种子或其提醒覆盖。

## 请求时间与取消

- 延续数值型 timeoutMs，以 0 明确表示不附加总时限；普通服务缺省、仓库 .env.example 和手工 CLI/隔离驱动均为 0。
- Service 和 NativeEngine 只在显式正 timeoutMs 时创建总计时器；0 不得传给 setTimeout 而变成立即超时。既有显式数值配置保留兼容，其合法性仅限整数及底层计时器可表示范围。
- PoolConfig 手工模式允许 timeoutMs=0，CLI 使用 0；Node 仅对显式正预算启用池计时。有限 acceptance 仍使用原有 30 秒、三次/128 tokens 预算。
- HTTP 层不另加请求等待空闲时限；Node 的请求接收时限也不沿用自动验收预算。
- 前置断开、排队取消和服务关闭继续传递 AbortSignal，清理自身连接和进程，等到真实 idle 后释放串行槽位。手工驱动读事件不附加旧 50 秒预算，TLS 等待宿主核验也不附加旧 5 秒预算；前置取消和私有通道关闭负责收口。有限验收的核验预算、初始化探针及取消后的强制清理预算保持用途独立。
- 不承诺消除运行时或底层网络库自身错误；连接重置仍如实记录白名单故障码。

## 正文和队列

- Bun 1.3.14 的 maxRequestBodySize=0 实测拒绝正文，HTTP 使用底层可表达的大范围，不再自行施加 2 MiB 产品策略；idleTimeout=0。
- 手工 TLS 入口不使用 REQUEST_LIMIT；该常量若仍被有限自动验收使用，须标明测试用途。
- 去掉会对模型正文生效的私有 JSONL 8/24 MiB 门槛及捕获正文 2 MiB 门槛；保留 UTF-8、JSON、字段类型、请求/进程归属、状态顺序和 EOF 完整性验证。
- 去掉 Service 的 16 个执行/等待请求拒绝条件，仍通过已有队列串行运行，取消与关闭覆盖全部队列项。
- 日志继续有界保存预览并对完整观测字节计算哈希；观测失败不能触发模型重放，也不能假称拿到了完整原文。
- 隔离凭据在原生 ready 回调中、投递业务正文之前逐物理进程核验并保留启动证据，不能根据大正文处理后的不完整 /proc 环境读数误判凭据变化。
- 大正文对照显示原生直达 TLS 回环成功，而 Bun 隔离代理转 Node 接收端出现解密错误；改由隔离命名空间中的专用 Node 进程透明转发 TLS。复用原固定 CONNECT 目标和拒绝探针，端口/计数经结构化私有帧回传，关闭时只清理自身子进程和临时 bundle；不让代理取得池 Key。

## 兼容与交付

- 旧显式预算测试保持；默认无预算只用于用户桥接/手工链路，不允许自动真实验收借模式或 0 绕过小预算。
- 更新 docs/api.md、README 和实际受影响的既有 Spec 场景，不扩展到新的网关功能。
- 本轮验证原版 293 + 当前 preload，当前 8787 只在离线检查通过、活动请求收口后有序替换为新轮次；保留旧日志与 8791 报告。
- 现有轻量二进制内嵌旧桥接逻辑，本轮不把它冒充为已包含修复的产物；新轻量发布须另做重建及兼容验证。

## 风险与回退

- 原生种子放宽仅限内部 transport_context 用途；普通 API 保留守卫必须有负向回归。
- 移除本地准入后资源策略由前置负责，日志容量配置不随请求扩大。
- 现有 ECONNRESET 单独保留证据，不添加自动重试掩盖故障。
- 回退只针对本轮可审阅代码范围，旧运行目录和既有配置文件不覆盖、不删除。
