# 原生 CC 入站保真适配与全场景回归

## Goal

让桥接接收用户主要使用的原生 Claude Code 2.1.293 请求，保留业务正文和上下文，同时维持普通 API 的原生组装能力，重新验证全部既有场景及新增原生入站场景。

## Background

- 用户说明现有 cc2api 基本接收原生 CC 入站，本轮要求“按照你的方向来做，然后重测所有场景”。确认方向为原生正文保真、普通 API 原生组装、发送前明确校验。
- 当前入口只接纳窄正文键集合（src/shared/input.ts:5），已有 billing system 被拒绝（src/runtime/293/job.ts:18），不能直接接入完整原生 CC 请求。
- 原 23 场景为 15 次成功出站、5 次明确拒绝、3 次发送前超时；超时为强制工具选择、工具续轮、带工具历史的子代理，证据在 artifacts/scenario-compare-20261106/。强制工具选择须先核对固定版本能力，不将不支持的组合当成必须成功的请求。
- cc2api CLI 控制组 15 条样本保留 tools、messages 及 CCH 以外的 system。vm2api 源码有宽字段接纳和前置工具校验，但其本地 cli-node 与 README 哈希不符，不能复制 303 常量或据此授信；研究在 artifacts/vm-native-ingress-20261106/README.md。

## Requirements

### R1：区分原生 CC 与普通 API 输入

- 现有 HTTP 入口接纳完整、可识别的固定 293 原生请求，保留普通 API 和显式上下文信封用法。
- 原生识别依据结构化 billing、metadata 和实际头部/上下文证据；识别结果不授予凭据、执行或本地配置权限。
- 版本不支持、归因歧义和显式上下文冲突必须明确失败，不通过改版本字符串或猜父子关系继续发送。
- 普通 API 保持现有参数支持范围，本次不将其所有未知字段改成自动透传。

### R2：原生业务正文保真

- 保留 system 业务段、messages、tools、tool_choice、thinking、output_config、缓存边界及 thread、diagnostics、fallbacks、safeguards 等字段的 JSON 语义，不再添加默认 CLI system、提醒或工具。
- 原生省略字段保持省略；tools=[] 和省略均不增加工具。声明工具不替换、不额外加入 strict，也不在本地执行。
- 扩展 JSON 数据只作为上游正文，不得变成本地账号、代理、环境、工作目录或运行时控制参数；已知私有控制字段明确拒绝或隔离，不能静默丢失。
- 对 metadata、billing/CCH 和传输头建立必要改写清单，清单外不为模拟客户端而重组正文。
- 保真按 JSON 语义及缓存位置验收；HTTP 日志保留真实入站原文和字节哈希，不宣称改写后整个正文与入站逐字节相同。

### R3：身份、会话及请求归因一致

- 调用方凭据不用于上游；设备和账号身份由专用运行时环境提供，metadata 会话归属与解析后上下文一致。
- 保留可证明的 billing 会话后缀、prompt ID、轮次和父子标识，只改账号归属及最终 CCH 等必要部位；不能统一重标为主请求或 subagent。
- 覆盖 main、subagent、workflow、compaction、auxiliary、side_reply；原生头、metadata、billing 和显式信封冲突时明确拒绝。
- 合法端到端扩展头默认保留，连接级头和调用方凭据按既有规则处理；beta 和条件头不能未经核验就静默删除或伪造。
- 最终 CCH 由固定原生传输生成，独立接收器只观察和复算，不由 JS 重算替代最终发送。

### R4：前置校验及超时修复

- 按固定 293 实际能力校验 tool_choice、工具声明、thinking、模型和输出参数组合：支持时正常发送，不支持或畸形时及时返回具体 4xx，不等待预算耗尽。
- 定位并修复工具续轮、带历史子代理的构造超时，保留 tool_use/tool_result、thinking 签名和显式工具定义。
- 明确传播原生构造失败，满足单次发送、不重放、取消后退役及终态加 idle 合同。

### R5：全部场景重测并可视查看

- 原 23 场景逐行保留，记录新预期、HTTP 结果、发送次数、采集状态、最终 CCH 及相对旧结果的变化；成功与明确拒绝分别判定。
- 新增原生矩阵，覆盖业务段/缓存、线程、身份、六类上下文、工具历史、条件/扩展头及版本、冲突、不支持组合反例。
- 原版固定运行时和新精简运行时运行相同关键矩阵；保持已有单元、集成、原生、安全隔离及页面回归通过。
- 页面区分普通 API 组装和原生正文接入；新样本追加，旧 89 条历史记录不覆盖。最终出站只展示独立回环接收器的实际观测。
- 测试使用合成身份与凭据、专用 HOME/config/cwd 和无外网回环，不自动使用真实账号、付费推理或正式抓包。

### R6：固定运行时交付

- 固定官方 2.1.293 来源、Bun 基底及身份核验，不升级到 vm2api 的 303 画像。
- 原生适配变更后按现有构建/准入流程生成新精简产物，核对重复构建、独立部署、实际执行体和兼容证据。
- 完整部署总量不超过 27933052 B；重测初始化、首轮及暖请求时延，沿用安全和兼容优先，不恢复历史相对速度 1.10 门槛。

## Acceptance Criteria

- [x] AC1 / R1：两类输入正确分流，不支持版本和歧义输入在发送前明确拒绝。
- [x] AC2 / R2：原生逐字段语义及缓存边界对照通过，改写仅在有理由的清单内。
- [x] AC3 / R3：六类请求的 metadata、billing、头部和父子关系一致，调用方凭据不外传，合法扩展头保留。
- [x] AC4 / R4：原三项超时均有根因和新结果；支持请求成功，不支持组合明确 4xx，不再等待超时且不重放。
- [x] AC5 / R5：原 23 场景全部重测，新增原生矩阵逐行报告；原版和精简版完成关键矩阵及必需检查。
- [x] AC6 / R5：页面准确展示实际入站、中间值和最终出站，缺失状态准确，旧 89 条不变，桌面和手机可用。
- [x] AC7 / R5：真实上游请求为 0，全部已发送样本 CCH 独立校验，凭据及部分凭据不进入可查询日志。
- [x] AC8 / R6：产物身份、重复构建、独立部署、体积预算和时延记录齐备，失败候选不作为已交付版本。

## Non-Goals

- 不修改或部署 cc2api、vm2api，不采纳其未核验二进制或版本常量。
- 不增加多账号调度、账号登录/刷新、付费推理、上游重试、本地工具执行或多轮代理循环。
- 不宣称账号免封、TLS 指纹完全一致或旧性能门槛已通过。
- 不重写历史日志、填充虚假最终值或删除失败场景制造通过。
