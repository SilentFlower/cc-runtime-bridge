# 技术设计

## 状态与范围

用户已要求优先优化运行时体积。本设计尚待首次 Brief 评审，不能视为已经批准实施。目标平台保持当前 Linux x64 和固定官方 2.1.293，不改 API、账号配置、发送方式或进程模型。

## 方案选择

整体 UPX 高压缩已测到 74.96 MiB，但初始化探针增加约 5.3 秒且 RSS 显著增加。采用缓存精简重打包作为本轮方案：保留原版原生运行时和全部 2511 个嵌入文件，仅移除模块字节码、内置模块字节码及专用共享字符串表。约 104.29 MiB 的候选空间来自实际模块图统计，不是从 vm2api 复制产物。

新文件是源自官方 293 的精简构建，不能称为逐字节不变的官方发行文件。原版源哈希保持原值，精简产物另行冻结哈希。

## 生成链路

1. 从显式源路径读取文件，先核对原版大小、SHA256、ELF 类型、节表、程序头和固定模块图布局。未知标志、越界指针、重叠或不一致记录明确拒绝。
2. 按已验证记录重建 `.bun`：保留文件顺序、名称、原始内容字节、编码、loader、module_format、side、入口和编译参数；保留源哈希、模块信息字符串表、预链接图及对应文件索引、启动计数和运行选项。
3. 清空每个文件的 bytecode 指针，删除内置字节码及其专用字符串表记录并清除对应标志；更新相关偏移、节大小、程序头映射长度和节表位置。源码和资源按原字节复制，字符串终止及对齐必须满足已核对定义。
4. 对照全部文件名称和内容哈希，核对 `.text`、`.rodata`、`.bun_builtins`、`.data` 等原生节字节一致；其它保留记录逐项比较。只有明确列出的容器头、偏移及缓存记录允许改变。
5. 在新临时目录生成候选，验证后原子发布到新的输出目录。源文件、已存在输出和宿主安装均不覆盖；生成失败清理本次临时输出。

新增入口建议为 `bun run runtime:compact -- --source <原版路径> --out <新输出目录>`；产物为该目录内的 `claude` 及小型生成报告。部署不要求同时保留原版副本、UPX 工具或外部 Bun，但操作者可在部署目录之外保留原版用于回退。文件都位于已忽略的 runtime/artifacts 目录，不提交二进制或专有源码。

## 生成报告合同

生成报告是可复核证据，不是运行时信任根。字段为：

- schema_version：固定为 1；不支持的版本拒绝读取。
- runtime_version：固定 2.1.293。
- variant：固定 compact-cacheless，明确属于精简构建。
- source_sha256：原版完整文件的固定 SHA256。
- artifact_sha256、artifact_bytes：实际生成文件的哈希和字节数。
- module_count：固定源的文件记录数 2511。
- module_contents_sha256：按文件原顺序对名称、长度和原始内容哈希形成的确定性汇总；源和产物须一致。
- native_sections：各保留原生节的 name、source_sha256、artifact_sha256；对应值须一致。

缺失、类型错误或保留校验不一致都使生成失败，不能根据自报清单放行任意程序。实际产物哈希需在候选通过离线验收后登记到版本 profile，规划阶段不填写猜测值。

## 运行时接入与日志

- src/runtime/profile.ts 仍是版本和允许二进制身份的唯一来源；保留原版身份，增加经完整验收后固定的精简身份。verifyBinary 维持现有返回实际摘要的函数签名，未知摘要明确拒绝。
- NativeEngine 在启动校验后固定本次服务选中的执行文件摘要，每个作业重新校验并与该摘要比较。即使换成另一种已知构建，也须重启服务后显式切换，避免运行记录与执行文件身份错配。
- Engine.binarySha256 和持久 RequestRow.binarySha256 保存实际执行文件摘要；精简来源在引擎名称中明确显示。不能继续把原版源哈希当作精简文件哈希。
- CCRB_CLAUDE_BINARY 继续指定执行文件，不增加按请求头选择运行时、自动下载、自动回退或改宿主安装的路径。原生适配器和采集阶段合同保持现状。

## 验证与性能界限

使用同一台机器、相同模块探针、环境白名单、独立空 HOME 和隔离网络，顺序运行原版/精简版各五个新进程；不并行压缩、不清理宿主系统缓存。报告进程初始化中位数、各进程峰值 RSS、完整部署文件集合及额外磁盘/内存文件占用，不把探针称为 API 或模型性能。

验收要求完整部署集合不超过 140 MiB，启动中位增量不超过 500 毫秒，最大峰值 RSS 增量不超过 32 MiB。随后分别以原版和精简版运行现有 14 个原生回环场景，独立核对最终 CCH、各类上下文、响应逻辑字节、工具及 thinking 历史、HTTP/SSE 错误、取消及单次发送。

缓存清理后的预链接元数据和源码回退尚未经过实跑，属于实施首步的技术验证点。若无法同时满足保留合同和三项资源指标，保留当前运行时并回到方案评审；不得自动采用每请求增加约 5 秒的整体压缩版或未经验证的其它 Bun。

## 回退

保留原版支持与源文件。回退只需将 CCRB_CLAUDE_BINARY 显式设回原版并重启本地服务；两种身份均须通过固定校验，不修改账号或现有 cc2api/vm2api 配置。
