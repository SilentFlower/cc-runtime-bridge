# 对齐 vm2api 的运行时体积与速度并支持常驻复用

## Goal

在保留可验证原生请求行为的前提下，使桥接运行时的完整磁盘体积和处理速度达到 vm2api 当前固定产物的水平，并支持单账号常驻串行复用。

## Background

- 用户要求在真实账号和生产接入之前优先优化，已否定 140 MiB 的旧目标，并明确将单账号常驻串行纳入本轮。旧方案保存在 research/rejected-140mib-plan，不作为实施依据。
- 原版程序为 252755128 字节（241.05 MiB），SHA256 为 8968405e26db478af44eabc4635ab5ca557057b702a54460a59c13e1b253e978，身份现由 src/runtime/293/source-profile.ts 定义。优化前每轮新建进程并读取全文件校验；现已完成常驻与轻量实现，最终结果见 research/acceptance.md。
- 标杆固定为本机 /root/project/vm2api/share/wrap-cli/cli-node，SHA256 为 8484c4c58f4b7782a190f7cab7c8aa5d1f706ae26b2d2a5cafe81af070f0611b；它使用单份 JS、压缩可执行文件和常驻作业循环。另一份 cc-node 为 32484148 字节（30.98 MiB），不混用为标杆。相关入口和解包依据为 /root/project/vm2api/docs/INFERENCE.md:10、/root/project/vm2api/deploy/build-native-cli.py:94。
- 标杆五次新进程的 20 槽协议就绪中位数为 3.023789 秒，就绪后首轮和复用本地合成请求分别为 129.483 毫秒、13.876 毫秒。解压版及完整测量边界见 research/vm2api-init-comparison.md；这些数字不代表外网模型速度。
- 原版 2511 条嵌入记录中的字节码及共享表约 104.29 MiB，布局证据见 research/bundle-layout.json、research/bundle-cache-details.json。直接压缩原版得到 74.96 MiB，模块探针还明显变慢，证据见 research/probe-best.json、research/memory-fast.json、research/memory-best.json；该探针不能与标杆协议就绪直接比较。
- 新的同内核构建探针已导入必需接口，但普通压缩后仍为 32.63 MiB，尚未达到目标。构建、依赖闭包和会话作用域证据集中在 research/compact-feasibility.md；导入成功不代表请求兼容或速度验收通过。
- 开工后的准入实验又核对了显式过滤、BCJ2、静态依赖和纯工厂注解；当时最小归档为 29.75 MiB，尚未计入加载器，当时 A1 未通过，证据见 research/footprint-admission.md。用户随后已允许原生内核裁剪或调整构建基底；体积及速度目标、固定 293 源应用和原生行为回归要求继续保留，不再要求四个原生节逐字节相同。

## Requirements

- R1：以标杆 CLI 运行时为相同统计边界，完整运行时必需部署文件集合不大于 27933052 字节（26.64 MiB）；新增或外置的 Bun、JS、字节码、资源、启动器和动态库均须计入，不能通过外移依赖或仅压缩下载包规避体积验收。既有控制面公共依赖及构建缓存单列，运行所必需的原版副本不得排除。
- R2：保留官方 2.1.293 源应用的版本、原生构造、原生发送、上下文关联、工具和 thinking 历史、流式与非流式、取消及单次发送合同；允许裁剪 Bun 原生内核或调整可追溯构建基底，但必须验证实际原生发送、CCH 及头部合同。不能以替换版本字符串或未经验证的其它项目产物替代兼容验证，Bun 实际版本变化须如实登记。
- R3：源程序、实际 Bun 基底和优化产物分别具有可追溯的 SHA256、版本、生成工具和参数；只接纳验证后固定身份的产物，日志记录实际执行文件的哈希。未知、损坏或运行中被替换的产物明确失败。
- R4：提供可重复的生成、验证和使用入口；原版程序保持独立且不被覆盖，可显式恢复原版运行。
- R5：只使用合成凭据、独立 HOME 和无外网回环验证，不读取既有账号、不触发真实登录、刷新或模型推理。
- R6：以同机、相同合成请求与隔离条件下的 vm2api 固定产物为对照，从运行时进程及私有作业协议这一相同边界验证启动到首轮完整返回、就绪后首轮和连续复用请求的中位耗时。目标是不劣于标杆，测量容差为 10%；区分版本查询、协议就绪及真实模型性能，不能用模块导入探针冒充可服务初始化。控制面耗时另列，正常复用不能再次承担新建进程和全文件哈希成本。
- R7：单账号工作进程常驻，当前队列继续串行；账号身份、凭据来源、代理和配置绑定进程，不跨账号复用。每轮建立独立请求 ID、上下文、取消控制和日志状态；会话、主子代理及压缩身份不得被前一请求污染。
- R8：取消或工作进程故障须收口本轮，无法证明状态已清理时先隔离并重建进程再接收下一轮；迟到帧不能归入下一请求，不为恢复进程隐式重放已经发送的模型请求。

## Acceptance Criteria

- [x] A1：完整运行时部署文件集合不超过 27933052 字节，列出每个必需文件、总量、分发和运行时额外空间；早期 32.63 MiB 探针不能被接纳为达标产物；对应 R1。
- [x] A2：优化运行时通过现有原生回环场景，独立核对 CCH、头部和上下文，并保留响应字节、工具返回、取消及请求次数；对应 R2、R5。
- [x] A3：源程序、工具和产物身份均可核对，错误版本、内容损坏或身份不匹配明确失败且不回退演示；对应 R3。
- [x] A4：从固定输入重复执行生成和验证命令可得到合同一致的可运行产物，原版及其它项目文件不被覆盖；对应 R4。
- [x] A5：至少五次新进程及进程内复用对照中，启动到首轮完成、首轮和复用中位耗时均不超过同条件 vm2api 的 1.10 倍；记录样本、运行条件、RSS 与额外空间，不称为真实模型性能；对应 R6。
- [x] A6：构建差异、依赖保留和原生调用路径具有可复核证据，未知或未经验证的布局拒绝接纳；对应 R2、R3。
- [x] A7：多轮正常请求复用同一进程，交替 session、main/subagent/compaction、工具与 thinking 历史仍得到正确且独立的出站内容和关联；对应 R7。
- [x] A8：取消、流中断、进程退出和迟到帧后，当前请求不重放，下一请求可在干净的常驻或重建进程中完成；对应 R8。

## Delivery Constraints

- 先通过体积与实际执行身份的准入关卡，再集成常驻工作进程；最终仍须同时满足兼容及速度验收。
- 如果固定原生行为与目标体积不能同时满足，提交实测原因并保持任务未完成；不得静默放宽体积、接纳未经核对的内核、删减已支持请求或把外置依赖漏算。

## Non-Goals

- 不接入或修改 vm2api、cc2api 及生产链路。
- 不升级官方版本，不修改请求语义或重写原生发送。
- 不直接将 vm2api 的修改版客户端当作固定官方 293 的兼容实现，不把磁盘收益当作内存收益。
- 不加入真实 OAuth、账号池、并发调度、计费、公开管理或 V4。
- 不把官方程序或提取的专有源码提交到 Git。
