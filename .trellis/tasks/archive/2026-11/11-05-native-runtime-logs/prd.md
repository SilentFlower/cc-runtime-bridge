# 首版：官方 293 原生请求桥接、黑名单头策略与请求日志查看

## Goal

建立独立的 Claude Code 原生运行时桥接项目，保留请求语义和扩展字段，让每次请求的输入、处理及响应可记录、可查看、可核对。

## Background

- 用户搁置现有 cc2api 头部缺漏修复，要求先开独立项目，并询问黑名单是否更合适；黑名单及字段归属作为本次建议方案提交评审。
- 用户追加要求：记录和展示类似 vm2api 的日志。
- 官方 293 已离线验证预加载、内嵌模块访问、原版组装与响应截取；CCH 在原生发送链路才补齐。
- 仅强制改为 main 会与子代理 billing、agent 类型和父子关联产生不一致。

## Requirements

- R1：固定官方 2.1.293，复用实际构造与原生发送，不以修改版本字符串代表兼容。
- R2：结构化适配消息、system、工具、thinking 等字段，保留工具历史，不自动执行 API 调用方的工具。
- R3：请求头采用黑名单与字段归属，合法端到端扩展默认保留，每项处理可解释。
- R4：类别、agent 类型、agent ID、父 agent ID、session、prompt、metadata 与 billing 关联一致，已有子代理或压缩语义不得强制改为 main。
- R5：保留响应逻辑内容，覆盖流式、非流式、HTTP/SSE 错误与取消，首版完成单账号工作进程的离线链路。
- R6：日志关联入站、头部处理、CC 组装、可用最终采样和响应，原文可配置保存并脱敏。
- R7：提供本地只读日志列表与详情，支持筛选、原文查看、头部处理原因、父子关联及性能。
- R8：中间值、真实最终采样、未采集、截断、采集失败和流中断分别展示。
- R9：提供 off、summary、debug 模式，本地首版默认 debug；具有存储上限和保留策略，日志故障不得重放请求或阻塞响应。
- R10：默认用合成数据、空配置及无外网回环验证，不自动触发真实账号登录、刷新、付费推理或生产切换。

## Acceptance Criteria

- [x] A1：固定二进制可运行离线调用，版本、hash 或接口不匹配时明确报错。对应 R1。
- [x] A2：未知合法业务头保留，鉴权、连接级及 Connection 声明字段正确处理，页面可查看原因。对应 R3、R7。
- [x] A3：main、subagent、compaction 等夹具类别正确，父子标识与 billing 一致，缺省来源标明桥接默认。对应 R4。
- [x] A4：工具历史、文本与 thinking 相关字段按受支持合同适配，不支持的显式参数明确报错。对应 R2。
- [x] A5：状态、错误与响应逻辑字节保留，tool_use 返回调用方，取消和慢消费者不导致额外请求。对应 R2、R5。
- [x] A6：request ID 可关联各阶段及全部 attempt，进程退出后仍可查看持久详情。对应 R6、R7。
- [x] A7：列表筛选、详情原文、复制与关联查看可用。对应 R7。
- [x] A8：cc_prepared 不冒充 wire_final，缺失、截断、取消、流中断与采集失败按事实展示。对应 R8。
- [x] A9：写入延迟或故障不阻塞主响应、不重放，容量与保留规则生效且采集状态可见。对应 R9。
- [x] A10：日志没有测试凭据 canary，浏览器安全文本渲染，查询不触发模型或账号动作。对应 R7、R9。
- [x] A11：核心链路和页面在独立数据目录、合成凭据、无外网环境完成验收。对应 R10。

## Non-Goals

- 修复现有 cc2api、变更其账号配置或切换正式发送链路。
- 恢复已暂缓的 V4。
- 建设完整账号池、注册养号、计费及公开管理平台。
- 首版承诺跨账号或同进程多请求并行。
- 将合成测试视为真实 OAuth、服务端风控或封号率证明。
