# 技术设计

## 1. 边界与复用

新增可提交的测试工具，提取现有被忽略脚本中的采集原语，而不是把产品能力依赖到 artifacts 路径。预计入口为 scripts/test-pool.ts，配套工具放在 scripts/testing/，定向测试放在 tests/unit、tests/integration 或独立原生测试目录。

不修改 src/runtime/293、EngineConfig、生产发送目标、数据库合同或压缩配方。当前官方及精简身份直接复用；新增工具的构建不能引入精简源码摘要变化。

## 2. 数据与网络路径

```text
宿主测试控制端（读取受保护池配置、脱敏、报告）
  ├─ 无外网命名空间：测试 HTTP 入站 → 桥接 → CC → 本地 CONNECT
  │                                                    ↓ Unix socket
  └─ 宿主 Node TLS 采集转发器：真实 CC 最终请求 → 池 Messages
```

CC 和隔离测试驱动使用独立 HOME/config/workdir、合成身份及固定运行时。它们不接收池 Key 配置；隔离空间只启用 lo，CONNECT 只接受 api.anthropic.com:443，并连接固定 Unix socket，不解析或连接该公网地址。宿主转发器只向明确配置的池目标发起请求，遥测关闭；其他目标或 API 路径拒绝并记录。

网络隔离原语已有本地证明，完整实施仍须用原版和精简 CC 验证 CCH、归属和响应。

## 3. 配置合同

- 测试配置集中于宿主控制端和转发器；不为产品 readConfig 增加 Base URL。
- 使用显式 --pool-env 路径读取受保护 env 文件，不执行 shell source。可识别专用 CCRB_TEST_POOL_BASE_URL/API_KEY 与现有 PROJECT_REQUESTER_BASE_URL/API_KEY；冲突、缺项或非法值启动失败，不继承 CCRB_NATIVE_API_KEY。
- 本轮 model 固定 deepseek-flash；不读取现有配置的 Gemini 主模型或执行 fallback。首轮 maxRequests=3、max_tokens≤128、单并发；池请求预算 30 秒，CC 作业预算 45 秒，留出原生启动和清理时间。
- Base URL 仅接受明确的 HTTP(S) 服务地址，禁止 URL 用户名/密码、query/fragment 及 Anthropic 目标；真实池使用当前 HTTPS 配置，HTTP 仅用于本地夹具。/v1 尾部只出现一次，原生 /v1/messages 的查询参数保持。
- --live 才能发起真实池请求；普通单元、集成和构建全部离线。首次实施后的真实验收使用已确认池配置，最多三次，首个错误后停止后续真实调用，不自动重试、重定向或回退。
- 池配置和证书不进入 Git；Key 值不通过命令行或报告展示，Base URL 在本地报告只显示无凭据地址。真实 Key 只存在测试控制端/转发器，CC 子进程使用既有环境白名单。
- Key 仅接受 4–4096 位 A–Z/a–z/0–9/点/下划线/波浪号/连字符；不支持格式在宿主与 Node 初始化时拒绝，避免 JSON 转义后绕过已知秘密的原文字面脱敏。配置错误说明不得包含 Key。
- 默认真实账本仍为 first-run，已有文件排他拒绝。用户选择修复及新一轮最多三次验收后，显式 --live-run repair-20261106 使用独立账本；轮次 ID 限 1–64 位 ASCII 字母数字、下划线、连字符，不能自动生成轮次或覆盖旧账本，每轮仍保持三次与首错停止。
- 宿主已有 HTTPS_PROXY/HTTP_PROXY/NO_PROXY 时，真实池转发器复用这些标准路由设置，以当前 Node 的 --use-env-proxy 启用；只接受无 URL 凭据的 HTTP(S) 代理。配置仅进入宿主 Node，CC 驱动仍只继承 HOME/LANG/PATH，CC 自身的 HTTPS_PROXY 仍指向隔离空间内采集代理。离线模式不继承宿主代理；不读取或修改参考池配置中的其它字段。

## 4. 两段请求与响应

1. 独立 Node TLS 接收端先保留原始 HTTP 方法、path、版本、rawHeaders 和原始正文；启动原始重复头自检，校验失败则不开始模型作业。
2. 校验完整 UTF-8、JSON 及原生最终 CCH；独立计算只用于核验，不能生成、补写或修改原生 CCH。请求正文上限 2 MiB，超限或采集失败明确拒绝或标记，不用中间值替代。
3. 原始 CC 请求在第二段改写前固定。转发仅映射目标 URL、根 model 和池鉴权，重建 Host、长度及连接级字段；其他业务字段和合法端到端扩展头保留。原 CC 凭据及代理凭据不进入池，重建标准 Messages 的 x-api-key，处理原因逐项记录。
4. 第二段只调用池 Messages，JSON/SSE 不进行协议转换；不把池返回的模型名或内容伪装成 Claude。4xx/5xx 保留状态及逻辑响应字节；3xx 不追随，不产生第二次发送，明确报告未满足测试。
5. 流式采用背压，取消或关闭本地响应时中止池请求，正常 EOF 后才完成。断流、超时、取消与成功分别记录；清理有界，不为补日志重放模型。
6. upstreamStatus 仅在收到池响应头后记录；尚未收到时为 null，poolResponse 保持 null。本地合成 400/502 不冒充池状态，转发诊断单独记录 localStatus、outcome 与白名单 failureCode。

## 5. 采集与报告合同

测试专用类型及统一解码器放在 scripts/testing 的合同模块，不扩展生产 WorkerFrame 或 CaptureStage。报告 schemaVersion=1，使用真实 requestId/context 关联：

- ingress：实际测试 HTTP 入站文本及明确的合成场景来源。
- ccPrepared：传输前中间值，不能称为最终。
- ccFinal：Node TLS 实收值，含 rawHeaders、有界脱敏正文、原始 SHA256、观测/保存长度、完整性及 CCH 核验。
- poolPrepared：转发器提交给池客户端的参数、model/头部改动原因及明确的组装表示；未在池端观测的头不能冒充第二段原始网络头。
- poolResponse、bridgeResponse：池逻辑响应与调用方收到的逻辑响应，标明真实池/本地夹具来源、状态、字节、哈希和取消/断流结果。

请求和响应捕获预览最多 1 MiB；完整响应继续流动，哈希按实际观测字节计算。所有已知池/合成秘密先注册到 Redactor，再保存文本、头部或错误；截断、跨片段秘密和错误回显都有反例验证。控制端错误使用受控中文说明，不输出私有管道原文。

测试转发器和驱动各按请求建立脱敏上下文，防止上一响应的敏感名称标志头（例如 allow-credentials=true）被注册后污染下一请求预览。已经保存的真实回执保留原样；需要比对脱敏前请求时使用原始 SHA256，不能反向替换脱敏标记或重放推理。

隔离测试服务使用日志 off，防止不知道池 Key 的生产日志器提前持久化池错误回显；测试 Engine 包装器将必要事件经私有通道交给宿主，由持有池 Key 的报告端统一脱敏。这不改变生产日志实现或响应字节。

报告写入独立 artifacts/pool-tls-forwarder-* 目录，提供本机只读报告页，分别显示 CC 最终出站与池转发参数，并展示实际响应和变更原因。文本安全转义；服务器仅开放报告及静态资源，不暴露配置、证书或任意路径，查看页面不重新发起推理。原有 8787/8788 预览和历史记录保持。

## 6. 验证与失败行为

| 条件 | 预期 |
| --- | --- |
| 配置非法、Key 缺失、rawHeaders 自检失败 | 启动/配置失败，零池模型请求 |
| 意外目标、非 Messages 路径、正文超限或 CCH 不符 | 不转发，记录失败位置及原因 |
| 池 401/429/500、网络错误或 3xx | 单次尝试，原错误/未通过结果可见，不回退模型 |
| 池慢响应、客户端取消、SSE 断流 | 有界取消/清理，不伪造完整响应 |
| 池回显 Key、头/正文秘密跨片段或被截断 | 转发语义保持，持久报告与页面无秘密 |
| 新报告查看/刷新 | 零新增模型请求，既有样本不改写 |

离线夹具覆盖原版/精简、普通 API/原生入站、preserve/sub2api、JSON/SSE/取消和故障；其控制端和假池也在额外的无外网命名空间，CC 驱动使用嵌套隔离空间，经 Unix socket 相连。真实池只运行精简版的三个小场景：原生主请求 JSON、原生子代理 SSE、原生主动取消 SSE。每次显式 max_tokens≤128，串行且首错停止，避免用全套故障矩阵触发实际推理。

## 7. 回滚与范围

停止测试控制端即可关闭转发器和隔离进程，删除本轮临时配置/证书可回收本地测试资源；不改现有服务、运行时或池配置。原始 CC 最终请求与第二段池请求始终是两个不同观察对象；池调用成功不能代替 Anthropic 鉴权、缓存命中、生产最终采集或完整场景兼容结论。
