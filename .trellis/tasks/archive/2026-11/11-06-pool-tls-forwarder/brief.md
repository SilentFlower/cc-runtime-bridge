# Brief — 本地 TLS 采集转发到池内 Messages

## Goal

- 采集 CC 原生最终出站，并通过池内 deepseek-flash 验证真实 Messages 响应。

## Scope

- 本地 TLS 采集转发器、可重复测试入口及两段请求的只读报告页。
- 原版与精简的离线验证，以及首轮最多三次真实池验收。

## Non-Goals

- CC 侧 Base URL、原生装配和精简运行时改动，OpenAI 协议转换及生产自动最终采集。
- 真实 Anthropic/OAuth、遥测开启、付费缓存命中和池内路由审计。

## Technical Overview

- CC 在无外网空间经本地 CONNECT/Unix socket 进入 Node TLS 接收端，先记录原始头、正文并核验原生 CCH。
- 仅在第二段使用池 Base URL、deepseek-flash 和池 Key，Messages JSON/SSE 直接转发，取消向池传播。
- 报告分别展示中间值、CC 最终出站、池转发参数及真实响应，标明表示、来源、脱敏和完整性。
- 池 Node 端复用宿主标准 HTTP(S) 代理，CC 的隔离代理与环境白名单保持独立；未收到池响应时保留 null，本地 502 单列。

## Context & Decisions

- 池 Messages 兼容已由用户明确；Base URL 只改在本地采集转发器。
- 现有受保护池配置已找到，只读复用地址和 Key；本轮固定 deepseek-flash，不沿用其中的 Gemini 主模型。
- CC 使用合成身份和专用目录，不接收池 Key 配置；遥测关闭，不直接连接 Anthropic。
- 首轮真实验收最多 3 次、串行、每次 max_tokens≤128；首个错误后停止，不自动重试、重定向或换模型。
- 首轮失败后，用户选择修复上述两项；修复轮采用独立 repair-20261106 账本，最多三次/128 tokens/串行/首错停止，保留首轮回执。

## Risks

- 池可能拒绝部分 Claude 字段；保留真实错误，不能通过自动删字段或换协议制造成功。
- 池错误可能回显凭据；由持有 Key 的测试控制端统一脱敏，报告与配置隔离。

## Acceptance

- 原版与精简的本地回环证明原生 CCH、rawHeaders、业务字段保留和两段模型/凭据边界正确。
- JSON、SSE、取消及故障有界，单次发送；报告显示真实响应和明确的失败/截断，秘密不落盘。
- 最多三次真实池验收覆盖非流式、流式及取消，实际结果可检查，查看报告不再推理。
- 现有运行时、预览和历史样本保持；生产最终采集能力仍如实标为未实现。
