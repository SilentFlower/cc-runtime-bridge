# 技术设计

## 1. 任务边界

本父任务协调两个独立子任务，产品实现分别归入缓存策略和遥测开关子任务。缓存先实施，遥测随后在同一代码基线上接入，最后执行组合回归；任务树不代替实施顺序。

沿用现有控制配置 → EngineConfig → 环境白名单 → 固定 worker 的配置链。新控制值不进入 Messages 请求合同，不读取调用方同名头或正文扩展作为配置。

## 2. 配置合同

| 配置 | 接受值 | 默认值 | 生效方式 |
| --- | --- | --- | --- |
| CCRB_CACHE_POLICY | preserve、sub2api | preserve | 重建服务/引擎及 worker |
| CCRB_TELEMETRY | off、on | off | 重建服务/引擎及 worker |

新共享策略类型及解析入口集中管理枚举与默认值。readConfig、直接 createEngine 调用及 worker 边界均需要明确校验；后两者不能因绕过 HTTP 配置入口而获得不安全默认值。非法值在启动/配置核验阶段失败，不降级成另一策略。

worker_ready 增加可选能力及实际策略回显，由共享协议边界校验。旧握手只兼容 preserve/off；显式开启 sub2api 或 on 却没有相应能力时，控制层按受控配置错误隔离进程，不发送业务请求。遥测状态由真实 worker 报告，区分 off/pending/initialized/suppressed/unavailable。

GET /api/health 增加已配置策略的只读投影，明确表示启动配置，不能称为已上传或缓存已命中。现有页面保持只读，不增加管理接口；demo 不初始化原生遥测，也不作为开启成功证据。

## 3. 缓存策略原则

默认 preserve 完全沿用当前行为。sub2api 是借鉴候选位置的保守策略，具体规则由缓存子任务规定：调用方拥有的 message 标记与根自动缓存优先；只在明确可优化时替换 SDK 自动消息标记或补齐空白请求。system/tools 及其 TTL/scope 保留，调用方显式消息标记不清除。

策略只在唯一真实发送边界运行；本地初始化种子不应用策略。所有改动在 cc_prepared 与 Ree 前完成，由原生传输生成最终 CCH。策略结果作为可选、已校验的 cc_prepared 诊断投影写入已有 capture.note；历史缺失字段继续可读，不新增 SQLite 列。

## 4. 遥测原则

off 保持现有关闭行为。on 仅启用固定 293 的官方第一方事件链，尊重其账号、提供方和本地策略条件，不引入 OTel 第三方 exporter、自制事件或独立身份源。

worker 在本地初始化及 bootstrap 期间始终关闭遥测；完成后才按启动配置初始化官方第一方 logger。自动更新、错误上报及远程功能配置获取仍分别关闭，避免翻转 NONESSENTIAL 时顺带启用这些功能。

遥测批处理不进入模型响应背压链；关闭服务时在原有进程宽限内进行有界清理。是否真正上传由原生资格和网络决定，配置 on 不等于上传成功。

## 5. 兼容与验证

- 两项新增配置均省略时，原版及精简运行时通过现有完整原生场景；预览服务和既有日志数据目录不作测试写入。
- 子任务各自给出单元、配置边界、原生发送和精简构建证据；父任务验证 preserve/off、sub2api/off、preserve/on、sub2api/on 四种组合。
- 所有原生验证使用固定官方文件、独立 HOME/config、合成凭据、无外网命名空间和本机接收器。核对实际出站正文/CCH、模型请求计数、遥测请求及退出结果。
- 构建继续受 27933052 B 上限与实际执行体哈希核验约束，记录启动和暖请求时间；此前已取消的 vm2api 相对延迟门槛不重新作为验收门禁。
- 若官方开关或精简闭包不能满足上述能力，在接纳新产物前停留于失败证据并修订设计，不登记部分通过的产物。

## 6. 回滚

设置 preserve/off 并重建服务即可回退运行行为。未接纳的新产物不会替代既有已验证运行时；原版文件与既有精简产物不覆盖。日志新增内容走可选字段和现有说明，旧数据不回填。
