# 请求日志管理设计

## 边界

- 本轮面向 cc2api 管理端请求记录与 V3 账号的 CC 组装后快照。本仓独立日志工具的 summary/debug 作为内容分层参考。
- 请求摘要继续通过 DiagnosticsStore 的有界队列写入，完整内容继续使用现有按账号私有目录。管理端经既有鉴权和请求/尝试归属链读取。
- 与原生预热、提速及会话池任务顺序实施，最后进行联合回归；共享 gateway、native_contract 和诊断合同在同批消费者中同步。

## 日志模式合同

- 新增全局设置 `request_diagnostics_log_mode`，只接受字符串 `info` / `debug`，默认 `info`。缺键或历史非法值读取时回退 info；PUT 在任何写入前完成校验。读取失败保留已生效缓存，首次装配沿 info。
- 启动加载及保存设置后刷新网关内存缓存。管理员在请求记录页切换模式，沿用统一 API client 与字符串设置合同，显示保存中、实际模式和错误。
- 每个请求在入口冻结实际模式，排队和处理中切换全局设置不改变该请求。请求与尝试摘要增加可选 `log_mode`，旧记录缺省显示历史未知，保持原时间和归属。
- 私有 NativeSubmission 增加受信任的模式字段，缺省 info，未知枚举拒绝。模式只由网关冻结，调用方 body、headers 或 context 无法覆盖；保持现有私有鉴权、账号/环境/代次及截止校验。
- info 在完整内容克隆和持久化之前关闭采集，只保存现有白名单摘要、实际模式和采集状态。debug 还须满足现有账号采集目录资格，沿用脱敏、单份截断、权限、并发及超时保护。
- `capture_status=disabled` 保持兼容，配合实际模式区分 info 与账号未启用采集；保存、丢弃、失败、超时仍沿现有状态。历史内容不按当前模式倒推。
- 已保存 debug 快照在有效期内仍可读取；切换 info 对新请求生效。既有 messages 的 429/非流式请求与响应专项日志也消费同次冻结模式：info 只输出白名单摘要，debug 还须满足原专项开关及采集政策。避免通过其它日志出口持久化完整内容；本轮不新增响应正文采集。服务日志文件和容器日志的物理轮转沿原部署配置，七天回收范围为本轮受管理诊断数据。

## 弹窗与异步归属

- RequestDiagnostics.vue 复用 ui/dialog 的受控 Dialog、DialogContent、DialogHeader、DialogTitle、DialogDescription，详情区域设置固定最大视口高度与内部滚动。
- 点击列表记录立即打开带加载状态的弹窗，再加载请求摘要与实际尝试；快照仍按当前尝试读取。列表筛选、分页和滚动位置保持。
- 列表读取与详情读取分别管理 AbortController 和 generation，避免打开/关闭详情取消独立列表刷新。关闭、切换请求或卸载时取消旧详情读取并使迟到结果失效。
- 弹窗沿现有组件处理 Escape、关闭按钮、焦点约束和焦点返回。请求头和值、正文只用 Vue 文本渲染，保留截断、采集阶段与失败状态说明。

## 七天保留合同

- 请求根摘要及其尝试按请求开始时间保留 7 天，采用 UTC；早于 `now - 7 days` 进入清理范围，等于边界保留。保留天数固定，本轮沿已确认值实施。
- DiagnosticsStore 保留现有启动及每小时清理。使用当前进程真实在途请求集合保护进行中请求，完成/取消/Drop 后释放；重启遗留的 unfinished 记录按时间清理。保护集合有界于实际请求生命周期。
- 数据库删除仍在事务中先处理关联尝试再处理请求，兼容 SQLite/PostgreSQL。正常查询应用保留期与在途例外，后台清理失败计入可见健康状态并等待后续周期。
- 私有快照按自身 `captured_at_ms` 保留 7 天，早于同样边界过期；容量和数量限制可提前回收。读取只做有效期判断并返回明确 expired 状态，物理回收由后台完成。
- bench AccountRuntime 增加独立的低频清理生命周期，启动执行一次、之后每小时执行。使用持久环境目录列表和 `_root` 校验，覆盖运行、停止和休眠环境；目录遍历不调用 ensure/transport，不唤醒环境。
- 文件清理只覆盖受管理环境的 `flows/api/cc-prepared` 中符合 UUID 命名的普通 JSON 快照；目录及文件拒绝软链接，读取沿 O_NOFOLLOW、大小和 schema/账号/尝试归属检查。临时写入文件不按普通快照删除，沿现有写入器处理。
- 清理按批次、单次目录/文件预算执行，错误只保存受控计数与阶段。旧目录规模较大时按游标继续后续周期，清理与租约心跳使用独立执行资源，避免影响 30 秒续期。
- 删除前复核文件身份与时间；并发写入采用现有临时文件原子重命名。保留期内继续每账号最多 50 份/100 MiB、正文 2 MiB、头 128 KiB 的保护。
- 无效、损坏、未来时间异常及读写权限故障按受控错误报告；清理只处理可确认归属且符合过期条件的快照。日志故障保持旁路。

## 兼容、发布与恢复

- 请求/尝试 JSON 增加可选字段，已有数据库表结构和历史摘要继续可读。新增设置默认只补缺键，显式 debug 保持。
- 网关、sender、管理 UI 与 bench 清理能力同批联合镜像交付。历史缺模式的私有作业默认 info，能力与采集状态如实展示。
- 发布沿项目精确 Git、CI 和部署 SOP；实际部署属于后续独立门禁。回退镜像与设置时保留账号身份、HOME、凭据、会话和业务成果。
- 七天及容量清理执行后，过期请求日志按设计回收。将保留策略切回旧版本只影响之后的保留行为。

## 验证重点

- info 实际落盘完整内容为 0，debug 内容完成秘密脱敏且归属正确；切换时排队/在途请求保持冻结模式，旧记录状态可读。
- 日期边界、跨时区、无流量、重启、在途请求、损坏快照、并发原子写入、软链接和错误账号均覆盖；清理期间健康、租约与请求完成保持稳定。
- 弹窗验证快速切换、关闭后的迟到响应、键盘焦点、长正文滚动、分页和筛选；API 管理鉴权、Cache-Control no-store 及故障状态继续生效。
