# 请求记录弹窗、日志模式与按天清理

## Goal

让请求详情通过弹窗查看，并用明确的日志模式与保留天数控制记录内容和磁盘占用。

## Background

- 用户追加要求：点击请求记录后弹窗展示，替换当前页面下方展开的详情；增加 info/debug，info 不记录完整内容；只保留指定天数的日志。
- 用户已接受统一保留 7 天，默认 info，debug 追加脱敏头和正文，并继续保留容量保护。
- 当前请求页面为 cc2api `web/src/components/RequestDiagnostics.vue`，项目已有 Dialog 组件和账号弹窗样式可复用。
- cc2api `src/store/diagnostics_store.rs` 当前按请求开始时间保留 8 天，每小时清理数据库摘要及尝试。
- `src/service/native_capture.rs` 当前对 CC 组装后请求保存脱敏头和值及正文，每账号最多 50 份、100 MiB，正文 2 MiB、头 128 KiB，按数量及容量轮转。
- 本仓独立日志工具已有 summary/debug 及摘要/正文保留策略，可参考其内容分层；本轮面向已部署的 cc2api 请求记录。
- 与 `.trellis/tasks/11-11-native-worker-prewarm` 的提速任务分别验收，关注 info 减少持久化开销及 debug 的有界采集。

## Requirements

- R1：点击详情打开弹窗，在弹窗内查看请求摘要、实际尝试与 CC 组装后内容；保留列表位置、筛选与分页。
- R2：弹窗支持关闭、滚动及既有键盘/焦点行为；切换请求、关闭或离开页面取消旧读取并隔离迟到结果。
- R3：提供明确的 info/debug 日志模式，默认 info。info 保存账号、模型、状态、耗时、用量、关联与采集状态摘要；debug 在现有账号采集范围内追加脱敏请求头和值及正文。既有 messages 专项内容日志也遵守 info 摘要门控，debug 继续受原专项开关限制。
- R4：模式对后续请求生效，记录反映该次实际模式；已有 debug 内容按保留策略管理，历史缺失内容保持真实缺失状态。
- R5：数据库请求/尝试摘要与账号私有请求快照统一按 7 天保留期后台清理，空闲期间也可回收；清理不依赖用户打开列表或发起新业务请求。
- R6：数量、总字节、单份截断、目录权限、管理员/服务鉴权、凭据脱敏、账号及尝试归属检查沿用现有保护。
- R7：清理只覆盖受管理的请求诊断表及 CC 组装后快照，不扩展到账号 HOME、凭据、业务会话、成果或其它抓包目录。进行中的请求和正在写入的文件按实际生命周期保护。
- R8：失败、截断、缺失及过期状态可见；日志与清理保持旁路、有界，不重放模型请求，不修改业务转发内容。

## Acceptance Criteria

- [ ] AC1：列表点击详情打开弹窗，筛选及分页保持；关闭/快速切换请求时展示归属一致（R1、R2）。
- [ ] AC2：info 请求完整头/正文持久化数为 0，已有专项内容日志降为摘要，诊断摘要及统计正常；debug 在账号允许范围内保存脱敏内容（R3、R6）。
- [ ] AC3：模式切换只影响后续请求，历史记录的采集及模式状态符合实际，缺失字段兼容（R4）。
- [ ] AC4：保留期边界前后、无新请求、重启、数据库与快照协同清理通过；保留期内仍执行既有数量/容量保护（R5）。
- [ ] AC5：清理期间并发写入、请求进行中、失效/损坏记录、软链接、错误账号与故障恢复验证通过，非请求日志数据保持原保护（R6、R7、R8）。
- [ ] AC6：前端构建、后端与清理回归通过，使用合成凭据及离线请求验证（R1–R8）。

## Non-Goals

- 新增完整响应正文采集、最终 TLS 采集、重写模型输入或更改遥测策略。
- 把请求日志清理扩展为账号、会话或历史任务删除。
