# 独立二进制与 cc2api 转发方式接入

## Goal

将本项目交付为独立可执行二进制，在 `/root/project/vibecoding-bench/cc2api` 中作为按账号选择、保留账号并发的原生转发方式。

## Background

- 用户明确要求二进制交付并接入 cc2api，已选择按账号配置及推荐的按需工作进程池方案。
- 当前 `v0.1.0-beta.1` 是源码 Release。本项目旧精简运行时实测为 27383864 B，现有 HTTP 控制服务和页面属于独立层。
- cc2api 是 bench 内独立 Git 仓库，负责鉴权、账号选择、凭据刷新、调度及统计；V3 的账号环境包含 network、CLI、sender 三个角色。
- 现有原生物理进程串行处理作业。cc2api 默认标准并发为 3，普通请求占 2 内部单位，Haiku 占 1 单位。
- 现有 sender 预算为 128 MiB。原生池需要显式配置并验证资源预算。来源、代码位置及仓库基线见 `research/integration-boundaries.md`。
- bench 的旧 `11-04-cc2api-cli-request-runtime` 已被用户暂缓。本任务按新的明确需求独立交付，一个端到端验收覆盖二进制、消费者和部署接入。

## Requirements

- R1：交付 Linux x64 独立可执行的原生发送二进制，固定官方 2.1.293 来源、构建配方、分发及执行体校验值，实测文件体积和部署依赖。
- R2：cc2api 在账号创建、编辑和读取中支持 `request_backend=legacy|native293`。历史及省略值默认 `legacy`；账号可独立启用与显式回退，运行中切换通过现有排空门禁。
- R3：原生方式覆盖 `POST /v1/messages` 的普通 API 和固定 293 原生正文，保持既有支持范围、请求头白名单、会话及主子代理关联，支持流式、非流式和取消。其他端点沿既有发送方式处理。
- R4：保留账号现有标准并发及 Haiku 加权规则。按需进程池隔离账号、凭据代次与请求根，每个物理进程只执行一个作业，终态和 idle 收齐后复用。
- R5：网关继续拥有鉴权、账号选择、稳定会话、并发/RPM、凭据刷新和用量观察；工作进程只取得当前 bearer 与受控身份配置。原生请求由二进制完整构造并唯一发送，错误保持单次提交语义。
- R6：账号 sender 中运行原生池，部署配置明确原生二进制来源与有限内存预算。缺能力、版本不符、预算不足、身份或代次冲突时明确失败。按用户新增确认共享只读执行映像并回收空闲进程，降低内存后再发布，保持账号加权并发。
- R7：以合成凭据和离线回环完成真实二进制到 cc2api 的验证，提供构建、配置、回退说明及新的 beta 二进制附件和校验清单。

## Compatibility and Scope

- 原有转发的默认行为、版本画像及错误恢复继续沿旧路径。原生方式使用固定 293 的实际构造规则；既有 Rust 正文/头部/CCH/TLS 改写设置属于旧后端。
- 原生入站保持固定 293 的版本合同；其他原生版本返回明确不支持。版本适配升级作为独立工作处理。
- 原生模型提交失败向调用方返回错误。账号显式切换作为恢复旧后端的入口；凭据恢复作用于后续请求。
- CLI 和 sender 继续使用独立角色。原生池的预算由部署侧显式配置，在既有有限账号总预算中校验各角色额度及 CLI 最低额度；开发中提供隔离候选配置和实测，真实部署参数由用户部署时设置。
- 二进制定位为 cc2api 调用的请求执行内核，管理与统计沿 cc2api 既有界面。
- 首版接入 bench V3 的账号 sender。缺少对应原生能力的部署选择新方式时明确失败，原有方式保持兼容。

## Acceptance Criteria

- [x] AC1：二进制在独立目录、隐藏源码/官方源及构建工具的环境中完成真实离线请求，双次构建身份和体积有可审计记录（R1）。
- [x] AC2：账号创建、编辑、列表显示与 SQLite/PostgreSQL 迁移支持后端字段，历史默认旧方式；两个账号独立选择，忙时切换拒绝，空闲切换及回退生效（R2）。
- [x] AC3：普通/原生 293、文本、工具往返、thinking、会话与主子关联、协议头多值/白名单、流式/非流式和取消均经独立 TLS 实收验证；非 Messages 端点原路径回归通过（R3）。
- [x] AC4：配置标准并发为 3 时可同时执行 3 个普通请求或 6 个 Haiku 请求，混合权重与现有准入一致；排队、降并发、取消、异常退役及后续重建可重复验证（R4）。
- [x] AC5：设备/账号、凭据代次和工作进程归属可核对，RT 不进入原生进程；变更及迟到帧隔离、上游错误及断线每请求最多一次模型提交、用量/许可收口具有回归证据（R5）。
- [x] AC6：原生模式缺二进制/能力、哈希错误、版本不支持和内存预算不足时明确失败；V3 三角色隔离与原 sender 布局回归通过，原生并发峰值和配置预算有实测（R6）。
- [ ] AC7：新 beta 提供与源码提交绑定的二进制、SHA256 清单和接入说明，消费者完成实际附件验收（R7）。

## Non-Goals

- 旧 V4 整体命名升级、CLI/sender 容器合并、新建独立管理后台。
- 新版官方运行时适配、透明转发任意端点或扩展本地工具执行能力。
- 自动部署生产、切换真实账号或调用付费推理。
