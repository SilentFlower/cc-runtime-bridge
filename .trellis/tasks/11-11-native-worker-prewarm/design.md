# 原生单进程预热设计

## 边界与目标

- 复用固定 293 二进制现有的 worker_ready 初始化能力。主要变更位于 cc2api 与 bench 调度器，本仓补充消费者离线夹具。
- 将加载前移到账号准备阶段。首个业务请求直接复用已就绪进程；预热只处理运行时资源，不执行模型作业。
- 适用启用的 V3 native293 账号。legacy 沿用原路径；现有账号资源模式、并发、物理上限及固定摘要保持原合同。

## 私有准备合同

- sender 新增独立的 `POST /internal/native/prepare`，沿用当前 binding.secret 服务鉴权。现有 GET `/internal/native/status` 保持能力查询语义。
- 新的预热信封包含：`account_id`、`environment_id`、`generation`、UUID `preparation_id`、`deadline_unix_ms`、`bearer`、`device_id`、可空 `account_uuid/organization_uuid`、`email`、`concurrency`。未知字段拒绝；含秘密的类型不派生 Debug。
- 绑定与截止校验复用既有规则：账号/环境/代次精确匹配，设备标识合法，单调预算最多 120 秒，固定分发体、执行体、封存、并发与有限/无限资源规则全部保留。
- 成功响应包含 `state=ready`、账号/环境/代次、`version=2.1.293`、协议、已验证 PID、实际空闲进程数和是否复用。成功必须晚于真实 worker_ready 与执行体核验。
- 正在准备时同账号同身份合并等待；已有匹配空闲进程立即复核并复用。已有业务占用全部当前进程时可报告 busy，后台预热不据此批量扩容。
- 准备失败返回现有结构化 AppError；超时、配置错误、身份/代次冲突及取消分别保留受控状态，日志只记录准备 ID、账号/代次、阶段、耗时和固定错误码。
- 准备取消使用同一私有边界中的独立控制操作，匹配准备 ID 和环境代次；不得取消其他准备或在途业务。取消结构只携带归属与控制标识。

## 池内执行

1. 提取并复用现有 checkout 的身份摘要、代次、分发体及映像校验；业务原始信封校验保持在业务入口。
2. 预热取得一个已完成握手的进程，不向 worker 投递 request_start/request_input。
3. 在池内当前 key 与环境代次仍匹配时，将进程放回 idle；旧配置结果退役。
4. 预热与业务共享启动去重和物理计数。正在启动的准备可被业务等待复用；业务正常按既有加权许可及按需扩容执行。
5. 异常、取消和 Drop 归还启动计数并清理私有目录、子进程及代理。维护或停用优先取消预热，再沿既有运行时排空规则继续。
6. 复用现有弱引用空闲回收任务，保留一个暖进程；映像缓存保持封存只读 FD。

## 网关协调与生命周期

- 网关拥有有界、按账号合并的预热协调器。队列只保存账号/环境/代次和触发原因，不保存 RT 或业务正文。
- 网关启动时，仅为启用的原生账号与已运行的绑定环境补偿准备；通过只读绑定查询取得当前环境。停用、休眠、维护和不存在的环境保持原状态。
- 独立服务可能先后就绪：启动后的 5、20、60 秒对尚未准备成功的账号执行有界补偿，ready 和正在准备的账号跳过；继续只读解析运行绑定，停止和休眠环境保持原状态。启动补偿窗口结束后沿后续明确事件或业务惰性路径处理。
- 账号切换到 native293、启用、身份/并发配置或权威凭据提交成功后，发出账号变更通知。消费者在实际执行时重新读取当前状态并遵守凭据所有权门禁。
- 调度器完成角色首次启动、唤醒或重建后，通过现有管理员服务鉴权入口发送“账号原生准备”通知。通知只入队，维护锁内不等待加载完成；原 transport 请求不会因重复通知产生递归准备。
- 网关使用现有凭据所有者获取当前 bearer，并通过私有 sender 准备接口传递。RT 始终留在网关。
- 旧代次、停用或后端切回 legacy 时取消对应准备；迟到完成结果经当前账号及环境复核后发布。
- 预热的 preparing/ready/busy/failed/cancelled 状态与真实握手事实可通过服务管理状态读取。环境基础 ready 与原生预热 ready 明确区分。
- 准备失败保留真实错误。后续明确准备事件或业务请求可按原惰性路径重建，业务模型请求继续保持单次提交。

## 兼容与部署

- 新接口使用同批联合控制/账号镜像交付；历史能力接口保持。旧 sender 缺少预热接口时返回明确能力错误，不能伪造预热成功。
- 固定二进制已有所需握手能力，版本与摘要按当前登记使用。
- 通知和只读解析复用现有管理鉴权、唯一账号绑定和维护锁；不开放浏览器直接控制 sender。
- 软件交付继续走精确 Git 计划、联合 CI 与既有部署门禁。部署验收限定“11-5”，保持 native293、并发 2、无限内存及现有采集开关。
- 生产准备验收使用零模型接口和真实进程证据。付费业务效果由用户后续请求观察。

## 验证与恢复

- 合成真实二进制预热完成后断言模型请求数为 0，再发首个合成业务请求，核对 PID/映像复用、原生头正文关联及一次模型调用。
- 对照冷启动与预热后提交至组装快照时间。验收以加载步骤前移及进程复用为准，2～3 秒属于现有样本下的预期，不设为上游响应保证。
- 覆盖双账号、凭据/身份/代次更新、重复准备、业务竞争、资源上限、启动失败、超时、取消、角色重建及 legacy 回归。
- 准备只持有运行时私有资源和内存状态；失败清理并保留固定状态证据。部署恢复沿旧镜像与原资源配置操作单执行，账号身份、HOME、会话及成果继续保护。

## 本地热路径提速增量

- 用户追加要求优化速度并对照 vm2api，纳入 R8。身份/遥测保留对照研究；会话池按用户追加决定接入现有账号政策。
- 已发现 native_status 和 native_forward 分别对 27,387,960 字节分发体做完整 SHA256；运行时微基准与完整 gateway/sender 开销须分列，不能把两者相减称为确定可节省值。
- 对重复验证建立安全复用方案：只复用已完整核验、保持打开的只读文件身份；每次校验真实路径、dev/inode、大小、权限与纳秒 mtime/ctime。文件替换、原地改写、权限或配置变化使结果失效；新进程启动保留既有精确 FD、固定分发体与执行体核验。
- 将能力与提交入口的廉价配置/预算/绑定检查与昂贵完整摘要区分，复用验证结果时保持原有失败关闭语义。
- 管理 HTTP 客户端复用仅限原有受控服务端点；账号秘密仍逐请求绑定，代次与剩余预算逐次验证。仅在阶段测量支持收益时实施，避免凭微基准更改业务传输。
- 使用小型普通 API 与约 790 KB、13 条消息、57 个工具的原生正文分组比较，再对照 0.25 核限制；记录实际出站字节和工具数，不能混用不同请求形状的绝对延迟。
- 同机微基准用于定位。生产 14 秒冷启动与 74 秒流内等待分别处理；模型、thinking/effort、业务历史和工具定义继续按原输入执行。


## 原生会话池接入

- 复用 AccountService.resolve_upstream_session_pool 及既有 Memory/Redis 实现。现有 enabled、size、ttl_minutes、refresh_policy 是唯一配置来源；普通 API 缺少已识别 CC 会话时保持原路径，不为池生成虚构成员。
- native 分支在账号选择和并发/RPM admission 之后、NativeSubmission 及原生 CCH 封口之前，调用既有 build_upstream_session_rewrite 一次。队列、粘性账号、用量和取消继续关联原始 body_map 与 session_hash。
- 原始正文、重复头和显式上下文冲突先沿现有入口合同检查。映射不能掩盖原来应拒绝的冲突或将损坏 session 变成合法输入。
- 仅当解析得到不同的合法上游 session 时，为原生发送准备独立副本：窄改 metadata.user_id 中的 session_id，并对同次 x-claude-code-session-id/context.sessionId 一致映射。账号身份、UA/SDK、billing/CCH 继续由固定二进制实际生成；不调用 legacy 整体正文重写链。
- 保留其它 metadata 字段、业务 system/messages/tools/thinking、Prompt ID、billing 轮次、agentId/parentAgentId/workflowRunId 及 thread.previous_message_id 的实际语义。父子关联使用原来的代理标识链，不把不同代理随机重标识；合成真实二进制用例验证映射后关联完整。
- 未映射、关闭、容量 0 或缓存失败时保留当前原生输入语义。缓存异常沿现有脱敏 warn 失败开放；没有额外模型重试或自动遥测激活。
- Diagnostics.session_context 接收原始 session 与本次解析结果。prepare_native_attempt 消费实际 cc_prepared 观察时保留真实/上游的两个摘要，检查实际组装 session 与映射目标一致；缺失或观察异常如实记录。
- 会话映射池只收敛 TTL 内的活跃上游 session 标识，运行时进程池仍按原并发和物理上限管理。共享上游 ID 不构成额外串行锁，业务历史与响应所有权保持每请求隔离。
- event_logging 继续沿既有只读映射：allow_insert=false，禁止创建成员、刷新 TTL 或临时重哈希。原生消息接入本身不启用二进制或旧自动遥测。
- 使用现有会话池开关可回退新增映射行为；池算法和持久账号字段保持兼容。联合发布与日志模式采用同批消费者。

## 会话池验证

- 复用现有 Memory/Redis 语义，用原生分支测试开关/0 容量、入池、池满、显式映射稳定、TTL、两种刷新、缩容及缓存失败。
- 隔离真实二进制至少覆盖两个真实会话共用一个上游 ID、同账号并发、不同账号、主/子代理、compaction、thread 前驱与原始上下文冲突，断言实际头/正文、prompt、billing 与响应归属。
- 记录接入后的阶段耗时，确认池解析只有一次且没有改变原生模型提交次数。预热和状态查询不创建会话池成员。
