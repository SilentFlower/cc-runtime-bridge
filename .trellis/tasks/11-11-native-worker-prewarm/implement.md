## 实现顺序

1. 在 cc2api 原生私有合同中定义准备/取消信封、受控响应及失败语义，读取所有消费者后再修改。
2. 扩展 NativePool 的零模型准备与去重，复用启动、映像、身份、资源计数、退役和回收；业务信封校验与执行边界保持。
3. 接入 sender 独立准备接口和 PreparedTransport 调用，覆盖鉴权、唯一绑定、单调截止及取消清理。
4. 增加网关有界预热协调器与受鉴权管理入口；接入启动、账号变更及凭据成功提交通知，失败状态可核对；增加 5/20/60 秒只读启动补偿，覆盖独立服务迟到就绪。
5. 在 bench 增加只读运行绑定解析及角色准备后的入队通知，覆盖首次启动、唤醒与重建，规避锁内回调重入及重复通知。
6. 调整本仓离线消费者夹具，在真实固定二进制与本地 TLS 上游验证零模型预热及首次业务复用。
7. 根据阶段计时优化已确认的重复摘要与受控管理调用开销，覆盖文件替换、原地改写、权限变化、并发失效和账号/代次隔离。
8. 在原生路径接入既有会话池解析、窄 session 映射与真实/上游诊断，保护原始冲突校验和本地历史隔离。
9. 用同条件冷/暖与大正文对照验证本地收益，完成会话池及日志模式联合回归，执行定向及要求的全量验证，进入 Check-All、规范评价及精确 Git 计划。

## 验证计划

- Rust 定向覆盖 prepare、重复/竞争、身份及代次更替、有限/无限资源、取消和错误能力；隔离管理服务首次只读绑定返回 503 后恢复，验证启动补偿、ready 去重及零额外模型调用。
- cc2api 必须执行 `cargo fmt --check` 与 `cargo test --locked`；真实二进制 ignored 用例通过本仓隔离夹具运行。
- 会话池定向覆盖开关、TTL/刷新/缩容、原始冲突、并发多会话及缓存失败；实际 CCH 与 prompt/父子/thread 通过真实二进制离线用例核对。
- 本仓执行 `bun run typecheck` 和相关离线真实消费者夹具，记录冷/暖耗时、PID/映像及模型请求计数。
- Python 执行账号运行时、只读绑定、生命周期通知与维护恢复相关 unittest，确认休眠/停用环境保持原状态。
- 对鉴权错误、错误账号、重复准备、迟到结果、重建、凭据轮换及零计费分别保存明确断言，避免只测函数调用形状。

## 失败恢复

- 准备失败按真实阶段记录，清理其私有资源；业务请求沿既有原生路径处理。
- 账号维护/停用取消对应准备，先收口再释放计数；旧回执按准备 ID 与代次拒绝。
- 发现跨服务锁重入、错误归属或凭据所有权异常时先停止受影响步骤，保留原数据与诊断证据，按实际失败范围恢复。
- Git、发布和部署的停止条件分别由原 owner/SOP 处理，不回滚其他任务的工作区改动。
