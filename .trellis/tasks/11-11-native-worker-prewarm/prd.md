# 原生转发预热、提速与现有会话池接入

## Goal

降低原生转发的冷启动和本地处理耗时，并让现有账号会话池设置在原生路径生效。

## Background

- 用户已选择账号启动、切换原生模式或重建时预热一个进程，沿用既有池；凭据更新后重新预热。
- “11-5”对应 bench 14、网关 12；现为 native293、并发 2、无限 RAM/swap，物理进程上限 4。
- 最近首条请求的原生提交到组装快照约 13,997 ms，第二、三条约 498/343 ms；首条快照后到响应头约 2,182 ms。证据为 bench 私有 `.deploy/native-egress-inspect-20261111/first-request-timing.json`。
- 原生池已按需启动、复用封存映像并至少保留一个空闲进程。现有 `PreparedTransport.native_ready`（cc2api `src/service/runtime_transport.rs:307`）只检查原生能力，首次业务请求承担加载耗时。
- 用户追加确认原生路径接入 cc2api 现有上游会话池，由现有账号开关控制。当前 native293 分支在 `src/service/gateway.rs:2309` 提前返回，池解析位于后续 legacy 路径 `:2372`。

## Requirements

- R1：启用的 V3 原生账号在启动、切换进入原生后端或角色重建后的准备流程中，提前准备一个可复用进程；实际握手完成后才报告预热成功。
- R2：预热仅完成本地加载和初始化，模型调用数为 0；不产生业务尝试、用量、会话内容或伪造的业务成功记录。
- R3：进程使用该账号当前权威凭据和身份。凭据、身份、环境代次或配置变化后，按现有隔离与退役规则重建并重新预热。
- R4：预热并发有界、同一账号去重，沿用既有物理进程上限、资源预算、按需扩容及空闲回收；普通请求可复用预热结果。
- R5：失败、超时、取消、旧代次和停用明确返回真实状态，收口已创建资源；维护和停用优先取消预热，休眠环境保持原状态；与业务请求并发时保持唯一归属和单次模型提交。
- R6：现有 legacy 后端、账号凭据单一所有权、RT 存储、头与正文生成、固定二进制校验及账号策略沿用原合同。
- R7：用合成凭据、离线真实二进制和本地 TLS 服务验证预热、首次复用、轮换、失败及并发；交付沿用精确 Git、联合镜像及发布部署门禁，生产验收限定“11-5”。
- R8：在同机、合成凭据、隔离回环上游中对照当前二进制和固定 vm2api 标杆，分别记录启动、就绪后首轮、暖复用及实际工作量；定位本地热路径后优化已确认的重复开销，保持请求语义、固定身份验证和单次提交。vm2api 对照用于研究，既有 1.10 倍历史诊断门槛沿原含义保存。
- R9：原生 Claude Code messages 接入既有账号级上游会话池，复用开关、容量、TTL、刷新策略及缓存原子映射。关闭或容量 0 时沿原行为；开启时在原生封口前一致映射 session 头、正文及同次上下文。真实下游会话继续用于账号选择、sticky、RPM、队列、取消及本地历史隔离，Prompt ID、轮次、父子代理和 thread 归属保持原语义。缓存异常失败开放，诊断记录实际映射动作及真实/上游 session 摘要。

## Acceptance Criteria

- [ ] AC1：原生账号准备成功时可观察到一个已完成真实 worker_ready 握手的可复用进程；同账号重复准备复用现有进程（R1、R4）。
- [ ] AC2：预热期间本地 TLS 模拟上游的模型请求数、业务尝试数及计费记录数均为 0（R2）。
- [ ] AC3：预热后的首次合成请求复用已验证 PID 与封存映像，单次模型调用、头与正文关联、正常输出通过；记录冷/暖阶段耗时（R1、R6、R7）。
- [ ] AC4：凭据、身份或代次变化后按账号重新准备；下一请求使用新身份和凭据，旧进程收口且与其他账号隔离（R3）。
- [ ] AC5：并发准备与业务竞争、初始化失败、超时、取消、维护、停用、休眠及重建通过验证，真实状态和资源计数一致（R4、R5）。
- [ ] AC6：有限/无限预算与 legacy 回归通过；真实模型付费验证由用户业务请求触发（R6、R7）。
- [ ] AC7：同条件对照保存标杆身份、样本与计时边界，分离运行时、控制面与真实上游等待；本地开销优化给出前后可复验数据，保持全部正确性与隔离回归（R8）。
- [ ] AC8：现有开关/容量 0、入池/命中/池满稳定映射、TTL、两种刷新策略、缩容与缓存失败在原生路径通过；多个账号及并发请求归属和单次提交正确（R9）。
- [ ] AC9：实际 CC 组装后头/正文/session 上下文一致，原始冲突仍被拒绝；多会话历史、prompt/billing、父子代理、compaction 和 thread 前驱保持独立，诊断真实/上游摘要与实际尝试对应（R6、R9）。

## Non-Goals

- 自动调用真实账号模型以热身。
- 更改现有会话池算法、增加第二套开关、给普通 API 预生成池成员或改变遥测激活策略。
- 批量常驻全部最大进程或新增全局资源放宽。
- 修改模型、thinking/effort、工具集、缓存策略或优化上游首内容等待。
- 升级固定 CLI/二进制、替代最终 TLS 采集或新增账号管理页面。
