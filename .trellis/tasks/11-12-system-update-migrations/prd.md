# 系统更新集成版本化数据库迁移与兼容验收

## Goal

让管理员在系统更新页面完成包含建表、结构迁移和兼容数据变更的常规升级，发布前自动验证升级与恢复路径，并消除无数据库变更时的兼容误拦截。

## Background

- 用户要求将建表和迁移纳入自动升级，避免常规发行显示“需要专项维护”。
- 本次 `system-ci-43065339778-1` 的 bench 合同为 `e7232926f126ec2a3ad60b3f346c4a7ad473d66497617acc6773c0c05117674b`。前三个旧发行的合同均为 `2de4434796c055c7b128be4b4546da54d571e94645237c0f3378815294bb1486`。两端 gateway 合同一致。
- `deploy/v3/system_release.py:20-47` 对包含建表或补列字样的整个 Python 模块计算合同。此次 `account_runtime.py` 增加预热状态查询导致合同改变；其 SQL 迁移函数 AST 保持一致。
- `orchestrator/system_update_contract.py:265-271` 要求目标受信声明包含原合同；当前发布策略仅认可自身。`SystemUpdates.vue:253-255` 据此禁用安装并显示“需要专项维护”。
- 现有 bench 和 gateway 已在启动时执行各自幂等初始化/迁移。系统更新已有排空、门禁、切换、健康检查和原镜像恢复。固定宿主执行器需要一次受控能力接入。
- `deploy/v3/SYSTEM-UPDATES.md` 记录原 US 免备份选择。用户在本轮选择自动两库快照，替代该功能范围内的原选择。

## Requirements

- R1：常规兼容建表、补列、索引和数据回填应随一次系统更新执行，自动校验执行前提、当前数据版本和完成结果。
- R2：数据库兼容合同基于明确的迁移定义和版本；非数据库业务逻辑变动应保持数据合同稳定。
- R3：发布前在合成旧数据上执行真实升级、重复执行和原程序兼容验收；签名发行的兼容声明必须来自实际证据。
- R4：两库迁移执行纳入原维护门禁和排空流程；记录持久进度、中断归属和可恢复位置，保持凭据、账号、会话、工作区和成果的数据语义。
- R5：用户选择推荐的自动数据库快照方案。升级维护窗口内保存并校验两库快照，限制保留量；迁移中断、候选健康失败和两库只完成一侧时，按原操作恢复一致数据及程序。恢复不得覆盖后来合法业务写入。
- R6：页面展示迁移计划、版本、执行阶段及具体阻断原因。兼容普通发行应提供正常安装入口。
- R7：提供现有已安装发行到新机制的接入路径，覆盖此次预热发行的升级阻断，并保留签名、精确镜像来源和宿主策略边界。
- R8：快照仅保存本部署两库及恢复元数据，按操作隔离和保护凭据；默认保留最近两组已完成快照，同时保护活动恢复依赖。空间或校验不足时停止本次切换并给出原因。
- R9：升级恢复与安装成功后的版本回退区分处理。重新开放业务后，回退保留后来写入的数据，按已验证的数据库兼容路径执行。

## Acceptance Criteria

- [x] A1（R1/R2）：只改预热等业务代码时，数据合同保持稳定，旧版页面可正常安装兼容新发行。
- [x] A2（R1/R3）：从含真实形态合成记录的旧库升级，实际建表/补列/索引/回填正确；二次执行结果一致。
- [x] A3（R3/R7）：CI 自动执行旧库到新库及原程序兼容演练，证据失败阻止发布可在线安装的声明。
- [x] A4（R4/R5）：在迁移前、中、后及两库不同完成阶段注入失败或重启，按确认策略恢复到一致状态。
- [x] A5（R4/R5）：账号凭据、设备身份、会话、额度、工作区、项目成果和原运行状态按其既有归属保持；恢复不覆盖后来合法业务写入。
- [x] A6（R6）：页面显示准确迁移阶段和可执行下一步，未知状态保持可见；常规兼容更新摆脱笼统维护提示。
- [x] A7（R7）：旧底座和旧签名材料的接入、在线升级、显式回退及中断恢复在隔离环境实际验收。
- [x] A8（R5/R8/R9）：真实 WAL 事务、空间不足、快照损坏、恢复中断、保留轮换及重新接单后的写入保护均通过故障验收。

## Constraints

- 本轮自动验收使用合成凭据和隔离数据库，真实付费模型调用为零。
- 本轮完整自动迁移、快照及恢复针对现有 v3 两个 SQLite 数据库；gateway 原 PostgreSQL 初始化及迁移行为保持兼容。
- 受信发行与兼容验证保持明确证据；自动范围是已登记、已演练、旧程序兼容的迁移。
- 生产数据库及部署操作沿独立上线授权执行。

## Non-Goals

- 自动生成任意 SQL、自动执行未知或破坏性删表/删列/语义转换。
- 外部 PostgreSQL 的自动备份、PITR 和跨数据库分布式事务。
- 在本轮代码实现期间操作生产数据库、接入生产宿主或自动安装新版本。
