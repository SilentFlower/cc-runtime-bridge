# Brief — 系统更新集成版本化数据库迁移与兼容验收

## Goal

- 让常规建表和数据迁移随系统更新自动完成，并消除普通代码改动导致的兼容误拦截。

## Scope

- 为现有两库建立迁移版本、执行台账和稳定的数据兼容合同。
- 接入升级前双库快照、迁移执行、失败恢复、空间预检和快照轮换。
- 在 CI 中加入真实旧库升级、新旧程序读写及回滚演练。
- 更新签名发行、旧底座接入及系统更新页面，覆盖此次预热版本的升级阻断。

## Non-Goals

- 任意 SQL、未知或破坏性迁移，以及外部 PostgreSQL 的自动备份恢复。
- 本轮代码实现期间的生产数据库操作和生产安装。

## Technical Overview

- 更新流程为：下载校验 → 排空 → 停止控制服务 → 保存两库快照 → 离线迁移 → 启动验收 → 恢复接单 → 清理。
- 安装过程中失败时，按原操作恢复两库和程序。重新接单后的版本回退保留后来写入的数据。
- 新迁移格式使用独立受信通道；旧目录保留原格式及有效签名。

## Context & Decisions

- 你已选择自动数据库快照。默认保留最近两组已完成快照，同时保护活动恢复依赖。
- 迁移范围覆盖 v3 的两个 SQLite 数据库。gateway 现有 PostgreSQL 行为保持兼容。
- 旧宿主执行器采用固定源码，首次接入需要一次受控底座升级。后续常规迁移通过系统更新页面完成。
- 自动验收使用合成凭据和隔离数据库，真实付费模型调用为零。生产接入按独立上线流程授权。

## Risks

- 快照需要额外磁盘空间；空间不足时停止切换并显示需求。
- 双库恢复依靠持久日志和关闭的维护门禁收口，中断后继续同一操作。
- 已重新开放业务后，升级前快照禁止覆盖当前数据库。

## Acceptance

- 普通查询及页面改动保持数据兼容合同稳定，兼容版本提供正常安装入口。
- 真实旧库的建表、补列、索引、回填及重复执行正确，新旧程序读写演练通过。
- WAL、两库部分完成、进程中断、损坏快照、空间不足和恢复中断均有可验证结果。
- 账号、凭据、会话、成果和后来业务写入按既有归属保持；快照保留规则正确。
- 旧底座接入、页面安装、失败恢复和显式回退全链路通过，页面显示准确原因和进度。
