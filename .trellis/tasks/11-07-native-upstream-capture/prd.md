# 原生上游配置、按需 TLS 验证与传输特征对齐

## 目标

通过可选启动配置选择上游及根模型，默认由固定原版 CC 直连；开启验证后，能观察最后一跳实际写出的 HTTP 字节，并对齐受支持范围内的 TLS 公开指纹和连接行为。

## 背景与证据

- `src/control/engine.ts:12` 尚无 Base URL，`src/control/server.ts:56` 集中读取启动配置。
- `src/runtime/293/job.ts:271` 使用同次内部 CC 账号身份和业务正文；`src/shared/native-input.ts:88` 的旧兼容补丁需要适应内部也使用自定义目标。
- 原先的双原版发送器方案只有第一跳采集；原生 curl 诊断不能逐请求完整采集复用连接，Node TLS 密钥日志也不覆盖原生 Messages 传输。
- 研究原型已证明：可控 TLS 通道可以完整转发原版 CC 的 HTTP 原字节，在 TLS 1.3、TLS 1.2、HRR、2 MiB 正文四组中，完整公开 ClientHello 与原版相同，最终写出与独立接收端逐字节一致。详见 `research/findings.md`。
- 以上为评审时的可行性证据；批准后的产品透明中继、连接生命周期、取消、长流与并发验收另记于 research/acceptance.md。

## 需求

- R1：验证能力内置、按需开启、默认关闭。关闭时不创建接收器、TLS 辅助进程或第二段发送。
- R2：可选 Base URL 与根模型覆盖；未配置时沿用内部 CC 的默认端点和调用方模型。历史消息、工具内部的 model 字段不受根覆盖影响。
- R3：端点、模型、凭据、代理及验证策略只来自本机启动配置，按实例冻结；业务请求不能改变运行目标，不自动继承宿主真实账号。
- R4：默认路径保持原版 CC 对外发送。验证模式允许使用固定画像的可控 TLS 通道，但完整公开指纹、HTTP 原字节和连接策略必须与固定原版基线独立对照；不能把模拟实现标作原版发送器，也不能只对比 UA 或 JA3。
- R5：开启后的最终采集来自最后一跳写出通道；绑定实际写入、刷出及完整性状态，独立区分第一跳实收、最终本地写出和上游实收。缺失、截断、失败可见，不用组装值或第一跳样本补写。
- R6：业务请求仍只由固定原版 CC 生成；CCH 的生成/省略遵循原生分支，设备及账号归属继续来自同次 CC；会话、父子证据和其他业务字段按既有合同保留，不做最终 CCH 的 JS 生成或第二次业务组装。
- R7：每个入站最多一次上游业务发送。保留会话隔离、取消、错误、长流及原生连接复用/关闭语义，不增加重试、重定向、模型回退或默认请求总时限。
- R8：配置、健康状态、模型选择和日志来源可核对；旧日志及显式池工具兼容保留。新辅助程序有独立来源与构建身份，不冒用原版二进制校验值。

## 支持边界

- 固定官方 CC 2.1.293，SHA256 `8968405e26db478af44eabc4635ab5ca557057b702a54460a59c13e1b253e978`。旧精简文件未重新构建、验证前不获得新能力。
- 正常直连支持 HTTP(S)；验证模式仅覆盖已登记的 293 Messages HTTPS/HTTP1.1 路径及已验证配置组合，不支持组合须明确拒绝。
- 配置仍走启动入口，网页只读；不新增账号管理或网页编辑器。
- 验证模式的 TLS 实现与原版不同；对齐范围是受支持协议字段和可观测行为，不承诺随机密钥、票据、物理时延或所有实现细节相同。
- 默认用合成凭据、实际原版程序和无外网假上游，不自动付费推理、不读取或修改受保护真实凭据文件。

## 验收标准

| 编号 | 可观察结果 | 对应需求 |
| --- | --- | --- |
| AC1 | 普通/完整原生输入覆盖未覆盖、仅端点、仅模型、双项覆盖；实际端点、模型及凭据正确，业务与归因保持 | R2、R3、R6 |
| AC2 | 关闭验证无额外验证资源或二次发送，原版/自定义目标的 CCH 状态正确，未采集明确可见 | R1、R5、R6 |
| AC3 | 从最后一跳实际写出取得完整 HTTP 证据，与独立上游逐字节比较；请求、连接和代次严格归属；部分写出、缺失、截断及失败可见 | R4、R5 |
| AC4 | 完整公开 ClientHello、实际密钥交换、TLS1.2/1.3、HRR、证书校验、有序头、重复头及实体对齐；连接复用、关闭后重连和恢复策略遵循原版实测基线 | R4、R7 |
| AC5 | 非流/流式、健康流 >30 秒、慢消费者、取消、断连及 HTTP/SSE 错误保持逻辑响应、清理及单次发送 | R7 |
| AC6 | 两个实际本地 CC 客户端并发，各自多个子代理；不同实例的端点、模型、凭据、session、agent 和分类证据不串 | R3、R7 |
| AC7 | 新旧来源、采集模式、健康能力、非法组合、构建身份和回滚说明一致；旧池工具及历史日志回归通过 | R1、R5、R8 |

## 不包含

- 复制 cc2api 的完整网关、账号系统或 reqwest HTTP 改写流程。
- 伪造版本、重算最终 CCH、隐式裁剪模型能力或隐藏不支持组合。
- 将少量原型通过称为完整产品验收，或承诺所有其他 CC 版本的兼容性。
