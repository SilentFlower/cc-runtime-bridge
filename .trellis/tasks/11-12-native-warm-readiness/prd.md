# 原生账号持续预热与首轮热进程复用保障

## Goal

使已运行的原生账号持续保持可复用运行时，让用户下次进入后的首条业务请求命中已就绪进程，消除可前移的本地进程冷启动等待。

## Background

- 用户确认零上游模型请求方案，并要求开始落实持续保温与首次业务复用。
- 2026-11-11 的实际首轮总等待为 14.33 秒，其中原生提交至 cc_prepared 快照为 6929 ms；后续三个请求同段为 180、185、55 ms。该段包含进程获取、初始化和正文准备，具体归因需要新增阶段证据。
- 实施前 `cc2api/src/service/native_prewarm.rs:51` 在启动后 5/20/60 秒补偿并消费变更事件；`:168` 返回上次准备结果缓存。
- 实施前 `cc2api/src/service/native_runtime.rs:982` 提供零模型准备，`:1190` 负责池身份及实际进程获取；原池保留一个空闲进程。
- 已完成任务 `.trellis/tasks/11-11-native-worker-prewarm/` 提供固定二进制、隔离回环及冷暖性能验证基础。

## Requirements

- R1：准备、巡检、页面读取和恢复只执行本地初始化及状态操作；上游模型请求数为零。
- R2：原生运行时可接单状态以当前账号、环境代次、内核代次及有效身份对应的真实进程为依据。准备完成后才公布就绪。
- R3：已运行且启用的原生账号持续接受巡检。进程退出或准备失效后重新准备，并保留至少一个空闲热进程；全忙时遵守原并发与物理上限。
- R4：预热与业务使用同一进程池和身份规则；业务取用时校验并原子占用当前进程。正在准备的请求沿既有预算和取消机制等待。
- R5：原生准备状态失效时显示准备中、忙、失败或未知；请求进入实际模型投递前完成本地准备。失败使用明确的现有服务错误并维持单次模型提交。
- R6：环境页展示真实原生准备状态、空闲数量、最近检查时间和失效原因；请求诊断展示实际 PID、复用命中与本地阶段耗时。
- R7：停用、休眠、排他维护、系统更新和内核切换继续遵循既有门禁；巡检只处理已运行环境。

## Constraints

- R8：固定 293 版本及摘要、业务正文/身份协议、会话池语义、现有资源限额与 legacy 行为保持原合同。

## Acceptance Criteria

- [x] A1（R1）：准备、巡检、故障恢复、环境页刷新全流程，上游模型 POST 计数为 0。
- [x] A2（R2/R3/R4）：预热完成并空闲 1 分钟、30 分钟、数小时后首个合成业务请求命中原热进程；PID、身份/代次和握手证据一致。长等待由可控空闲年龄覆盖，并补充真实空闲回收窗口验证。
- [x] A3（R3/R5/R7）：进程退出、凭据/配置变化、环境重建、网关重启及内核切换触发正确失效与恢复；旧代次迟到结果保持隔离。
- [x] A4（R4/R5/R8）：准备与业务竞争、全忙、取消、协议错误及资源不足均遵守原上限、预算和单次模型投递规则。
- [x] A5（R6）：页面与请求详情准确展示实时状态及复用/计时证据；历史缺字段显示未观测；移动端保持现有样式和可读性。
- [x] A6（R1/R4/R6）：同机、同正文、同资源条件比较冷与预热首轮；预热首轮新增进程启动次数为 0，记录本地阶段分布。预热首轮准备耗时应落在同条件稳定热请求范围；异常须定位并修复。
- [x] A7（R7/R8）：legacy、休眠/停用、更新维护、在线内核切换与回滚回归通过。

## Non-Goals

- 真实模型热身、真实账号自动推理或付费验收。
- 上游连接与提示词缓存预热、模型计算耗时承诺、修改用户的模型或思考参数。
- 升级二进制、扩大账号并发/内存/CPU、全量唤醒休眠账号。
- 本轮自动生产部署；交付后沿既有联合 CI 与部署流程执行。
