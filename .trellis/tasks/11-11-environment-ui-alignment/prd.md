# 环境页适配主后台风格与内核操作布局

## 目标

将「环境与任务 → 环境」整理成与主后台一致、便于扫描和操作的账号环境管理页，让用户直接识别运行状态并管理请求内核。

## 背景

以下代码位置描述改造前的取证基线；实现后的模块及验收证据见 `research/verification.md`。

- 用户明确要求优化环境页并适配现有页面风格。主后台使用暖白底、陶土色强调、系统正文和圆角卡片，见 bench 的 `cc2api/web/src/style.css:45`、`cc2api/web/src/components/Dashboard.vue:49`、`cc2api/web/src/components/Accounts.vue:907`。
- 环境内容经既有统一会话嵌入，见 `cc2api/web/src/components/Environments.vue:24`。bench 的 `webui/style.css:1` 使用终端配色、全局直角和扫描线，与主后台存在视觉差异。
- `webui/app.js:255` 以长段落和无样式按钮渲染环境。内核管理见 `:195`、`:220`，目前通过浏览器 prompt/confirm 完成操作；`orchestrator/main.py:12740` 按实际状态提供 `native_kernel`，灰度外为 null。
- 已有当地运行窗口、物理实测、凭据交接与维护入口。其展示口径分别由原任务 `10-20-v3-environment-panel-and-run-windows`、`10-20-v3-environment-physical-features` 以及运行时规范所有。

## 需求

- R1：环境页及该页内嵌入导航采用主后台的色板、字体层级、卡片、表单、按钮和间距。布局在桌面与手机均清晰可用。
- R2：按账号呈现环境卡片，首屏突出名称、环境状态、CLI/网络/API 三角色状态、资源摘要及请求内核当前版本。提供按名称/环境 ID 搜索与按实际环境状态筛选。
- R3：内核面板明确区分当前版本、已准备候选、上一版本与实际操作状态。准备使用版本输入弹窗；激活和回滚使用显示账号及目标版本的确认弹窗；错误在对应操作上下文展示。
- R4：保留当地运行窗口、凭据交接提示、物理实测和全部既有维护能力。长环境 ID、完整摘要、进程回执和物理特征放入可展开详情；停止、重建、画像校正等维护动作独立分组。
- R5：继续以服务器字段、灰度条件和预期状态版本作为准入依据。页面刷新、搜索、筛选和详情展开只读取数据。轮询期间保留搜索、筛选、展开状态与尚在编辑的表单，切页后旧回调失效。

## 验收

- A1（R1、R2）：与主后台并排比较，暖白底、陶土主按钮、圆角卡片、字体和导航层级一致；1280、720、390px 下无页面横向溢出，长 ID 和摘要可读。
- A2（R2、R4）：能搜索和筛选账号环境，区分就绪、停止、异常、未知及加载失败；展开后能访问原有详情和维护入口。
- A3（R3、R5）：合成夹具覆盖准备、激活、回滚、忙碌、候选缺失、灰度外、错误和待对账；提交保持原 operation_id、expected_revision、release 与 expected_sha256 合同。取消弹窗不提交操作。
- A4（R4、R5）：运行窗口与实测的来源/缺失提示保留；在轮询与切页场景中保留当前有效 UI 状态，阻止迟到结果覆盖和重复提交；读取页面不启动模型、环境维护或凭据操作。

## 范围外

- 其他业务页的整体换肤、技术栈迁移和 iframe 移除。
- 服务端接口、内核协议、灰度范围、账号身份、凭据、资源及调度政策调整。
- 生产发布操作；正式交付沿既有 CI 与部署 SOP 独立执行。
